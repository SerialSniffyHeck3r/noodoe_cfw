## 느렸던 이유와 변경

기존 BootstrapProvisioner는 NOR128MiB를 설치 전2회·후2회, 총512MiB 다운로드했다. 빈 영역과 기존 사진까지 읽어 비교한 것이며, 순정 사진을 전부 덮어쓰는 명령은 아니었다. 이와 별도로 원래 기기의 사진을 CFWPIC에 복사하던 정책이 있었다. 둘 다 새 기본 설치 경로에서 제거했다.

순정 FileTransfer의 최대 청크는11,816B, 기존 Bootstrap 저장소 명령은480B stop-and-wait였다. 이는 사진 한 장을 보내는 순정 작업과 대규모 백업·검증을 함께 수행하는 설치 작업의 차이이기도 하다. BT 칩 자체의 속도 부족으로 단정할 근거는 없다. 현재 런타임 HCI는921600bps이고 초기115200bps와 구분한다.

변경한 경로:

1. FAT·하위 디렉터리·기존 NVM 후보를 읽어 폰과 기기가 독립 감사한다.
2. 기기가9개 CFW 파일의 first-fit 할당을 직접 재계산한다. 호스트가 임의 마스킹 범위를 정하지 못한다.
3. 새 영역의 물리 preimage 총4,390,912B(4.1875MiB)와 FAT 변경 전후 자료를 폰에 fsync한다. 원래 파일 본문 전체는 보내지 않는다.
4. 변경하지 않는 NOR 블록은 기기 안에서 설치 전후 SHA256을 계산한다. 주소를 해시에 포함한다. 메타데이터는 폰의 독립 계획과 별도 비교한다.
5. 실제 데이터 청크는960B. FF만 있는 업로드 구간은 최대64KiB 길이 선언으로 전송한다. 소거된 FF 페이지의 불필요한 프로그램도 생략한다. 이미지 전체 해시·내용 검사·물리 readback은 유지한다.
6. 저장소 처리의256B 페이지마다5ms 쉬던 부분을 최대8회/2ms 작업 예산으로 바꿨다. BT·IGN·워치독 처리는 계속 양보한다.
7. 모든 파일 검증과 보존 검사가 끝난 뒤에만 Gate+Product staging을 허용한다. 재접속 시 완료된 파일/FAT/보존 해시를 재확인한다.

정상 Product의62..64 명령과 충돌하지 않도록 Bootstrap scoped 명령은80..83을 사용한다. 사진이나 설치 프레임 자체를 큰 힙 버퍼로 무제한 확장하지 않았다.

## 10분 목표의 현재 근거

최종 Release 내용으로 계산한 기본 전체 전송 payload는 약7,100,952B(6.77MiB)다. 기존의 **백업만512MiB**와 비교하면 전송 낭비가 크게 줄었다. 라이브 디렉터리·프로토콜 오버헤드·재시도는 추가된다. 헤더의 기기 UID/BL 해시는 시험값을 써 계산했다.

| 실제 유효 전송률 가정 | payload 전송 시간만 |
|---|---:|
| 10KiB/s | 약694초 |
| 20KiB/s | 약347초 |
| 30KiB/s | 약231초 |
| 40KiB/s | 약173초 |

NOR 해시·소거·프로그램, 재부팅 및 정상 실행 확인60초는 별도다. 따라서10분 목표는 정상 무선 전송률과 실제 NOR 처리 시간을 함께 측정해야 판정할 수 있다. 앱·기기 저널로 단계별 시간을 남긴다. 계산만으로10분 합격을 선언하지 않는다.

## 항상 새 설정·빈 사진 슬롯

- 최초 설치의 CFWCFG/CFWPIC는 기기 UID에 맞는 새 컨테이너다. 사진3슬롯의 A/B 헤더와 데이터는 빈 상태다. 벤치 사진·설정 또는 사용자 순정 앨범을 배포하지 않는다.
- 정상 업데이트는 시험 부팅 확정 후 RESET_PENDING 아래에서 환경설정(라이더 이름 포함)과 CFW 사진3슬롯을 초기화한다. 실패한 시험 부팅은 이전 설정·사진을 보존한다.
- 사진 초기화는6개 bank 헤더를 무효화하고 물리 읽기로 빈 상태를 확인한다. 중간 전원 차단 후 재진입해도 완료될 때까지 반복 가능하다. JPEG 본문을 보안 삭제하는 기능은 아니다.
- 빈 CFW 슬롯을 순정 WALL/album 파일로 대체 표시하던 Product 경로를 제거했다. 빈 슬롯은 실제로 비어 있다.
- 초기화 후 새 사진의 generation1과 옛 SDRAM 캐시의 generation1이 같아 옛 사진이 재사용되는 문제를 수정했다. 표시 중 빌린 픽셀을 덮지 않고 캐시 revision을 무효화한다.
- 순정 사진, 주행 누계, 정비 기준점, 복구본, 설치 기록, BT 페어링 키는 사용자 환경설정/CFW 사진 초기화 대상과 구분해 보존한다.

## 남은 한계

- 최초 FAT 파일 생성은 여전히 전원 차단에 원자적이지 않다. 파일 생성 도중 중단을 임의로 자동 재실행하지 않는다. 완료 후 staging 재개와 부분 FAT 생성 복구를 혼동하지 않는다.
- scoped 복구 자료는 전체 NOR 백업이 아니다. `expected.bin`은 sparse 계획 파일이며 장치에 전체 쓰기하면 안 된다. 앱 증거 폴더에 이를 명시했다. 기존 별도 PC 전체 백업 도구는 남아 있다.
- 신규 설치는 검증된 빈 클러스터에만 추가한다. 이미 같은 이름의 CFW 파일이 있으면 임의 덮어쓰기로 재설치하지 않고 실패한다. 기존 CFW의 일상 업데이트 경로에서는 확정 후 초기화 정책을 적용한다.
- 정상 SPP 사진 교체 UI는 이전 작업의 미완료 범위로 남아 있다. 이번 작업은 설치 시 사진 복사 제거·빈 슬롯·업데이트 후 초기화와 설치 전송 개선이며, 순정 수준 사진 전송 속도를 실측한 것이 아니다.
- 정상 BT 기판의 실차 설치·중단·버튼 순정 복귀와10분 이내 타이밍은 아직 검증하지 않았다.
