# 순정 시스템을 어떻게 이해했나

목표는 화면을 새로 만드는 것뿐 아니라 **기존 차량 정보 입력을 유지하고 순정으로 돌아갈 경로를 확보하는 것**이었다. 따라서 이 프로젝트의 역공학은 함수 이름을 추측하는 작업보다, 보존한 바이너리·통신 관측·실기기 결과가 같은 설명을 가리키는지 확인하는 과정에 가깝다. 저장소에는 순정 펌웨어 원본 덤프, 공장 설정, Bluetooth 비밀키, 전체 디스어셈블리 출력물을 공개하지 않는다. 특정 함수의 기계어 흐름을 어떻게 분석했는지는 [순정 어셈블리 분석](stock-assembly.ko.md)에 별도로 정리했다. [English](reverse-engineering.md)

## 증거를 쌓은 순서

1. **원형 보존.** 변경하기 전 MCU 내부 플래시와 외장 NOR를 읽고 해시를 기록했다. 순정 V5.16 APP와 하위 부트·공장 영역은 나눠 보존했다. 벤치 모듈의 BL 0.14와 실차의 BL 0.15를 같은 기기라고 가정하지 않았다.
2. **차량 UART 수동 관찰.** 115200 8N1, 시작 바이트 F5, 명령·길이·페이로드·XOR 구조를 확인했다. 계기판의 실제 ODO·연료 표시와 수신 바이트를 비교했고, 반대 방향의 A1 밝기 명령도 확인했다. 송수신 방향은 관찰로 정했지 배선 색만 보고 정하지 않았다.
3. **순정 APP의 코드 흐름 조사.** 명령 디스패처, GPIO 테이블, EVE 초기화, 업데이트·부팅 경로를 조사해 UART5, 세 버튼, IGN PG13, FT81x, NOR, Bluetooth HCI와 조도 경로를 찾았다. 코드 경로의 존재는 설계 의도를 보여주지만 모든 연식에서 그 장치가 실장·사용됐다는 증명은 아니다.
4. **순정 휴대전화 앱과 대조.** 원본 Android 앱의 페어링·파일 전송·기기 정보 명령을 조사해 순정 Bluetooth 전송 경로를 확인했다. CFW는 Classic SPP라는 전송 수단을 공유하되, 상위 메시지는 별도 NDCP를 쓴다. 순정 앱과 CFW가 그대로 서로 통신한다고 주장하지 않는다.
5. **주변장치별 브링업.** LCD·백라이트, 버튼, 차량 UART, NOR, 휴대전화 연결을 분리해 시험했다. 화면 결과는 가능한 경우 EVE 화면 캡처와 실기 사진으로 판단했다. PC에서 통과한 프로토콜 시험과 실제 바이크 시험을 같은 수준의 근거로 취급하지 않는다.

## 설계를 바꾼 발견

| 처음 떠올릴 수 있는 설명 | 확인한 사실과 설계에 미친 영향 |
|---|---|
| STM32가 LTDC와 전체 프레임버퍼로 LCD를 그릴 것이다. | 순정은 SPI로 FT81x EVE에 명령을 보낸다. CFW도 디스플레이 리스트·GPU RAM_G를 중심으로 구성했다. |
| 순정 송신 명령 01의 값은 버튼 네 개를 나타낼 것이다. | 실제 버튼은 서로 다른 액티브 LOW GPIO 입력이다. 01 명령은 통신 재요청·초기화 계통의 제어 흐름이다. |
| 화면의 연료 칸과 상태 바이트 하나는 곧바로 연료 퍼센트일 것이다. | 조사한 0칸·1칸 사례에서 특정 바이트 하위 니블이 일치했다. 별도의 바이트는 순정의 일반적인 6단계 위젯에 들어간다. 모든 칸·정확한 잔량 퍼센트까지 검증한 것은 아니다. |
| 파일을 끝까지 보냈으면 업데이트가 끝난 것이다. | 전송 수락, NOR 기록·재읽기, 설치 요청, 내부 플래시 교체, 새 APP 부팅, 정상 실행 확인은 서로 다른 사건이다. 앱 UI도 이를 분리해야 한다. |
| 키 OFF는 전원 완전 차단이다. | 상시 전원과 별도의 PG13 IGN 입력이 있다. 시동 종료 후 화면·백라이트·Bluetooth를 단계적으로 제어하고, 물리적 배터리 분리 없이 복구할 수 있어야 한다. |

## 확정과 미확정의 경계

**확인된 것**은 조사한 V5.16 이미지의 벡터·명령 분기, UART 실측 프레임 일부, 실물 전체 플래시와 OTA APP의 바이트 일치, 특정 주변장치 초기화 코드와 벤치에서의 브링업 결과다. **아직 남은 것**은 커넥터 전체 접점도, 미해석 차량 상태 바이트, 모든 연식의 BL·NOR·무선칩 리비전 차이, 차량 계기판이 밝기 명령을 실제로 적용하는 방식, 모든 전원 상실 조합에서의 장기 복구 결과다.

날짜가 붙은 옛 연구노트에는 나중에 수정된 가설도 남아 있다. 예컨대 내부 플래시의 16KiB 보존 재기록에 대한 초창기 설명은 후속 명령어 범위 검사에서 정정됐다. 상충할 때는 **후속 실측, 더 완전한 바이너리, 현재 코드**를 우선한다.
