# 0.9.40 버튼·복구·업데이트
이 설명은 대응 Product와 Gate가 설치된 0.9.40 기준입니다.

| 조작 | 동작 |
|---|---|
| 위 + O를 동시에 3초 | 즉시 MCU 재부팅. 저장·화면·Bluetooth 응답을 기다리지 않음 |
| 아래 + O | 퀵 세팅 |
| 퀵 세팅 위/아래 짧게 | 밝기 조절, Super Nite 중이면 해제 |
| 퀵 세팅 아래 0.8초 | Super Nite |
| 퀵 세팅 위 0.8초 | 주행 상태를 유지하며 LCD·EVE 재초기화 |
| 퀵 세팅 O 짧게 / 길게 | 닫기 / 메인 메뉴 |
| 키 OFF에서 O를 누른 채 ON → 2초 | Gate 복구 메뉴 |

위와 아래를 동시에 누르는 조작은 없습니다. 재부팅 뒤에는 모든 키를 놓으세요. 계속 누르고 있던 O 때문에 복구 메뉴로 잘못 들어가거나 재부팅을 반복하지 않도록 했습니다. 미완료 설치·손상은 Gate의 기존 검사로 판단합니다.

Gate 메뉴에 들어가는 것 자체가 순정 복원을 실행하지는 않습니다. 메뉴에서 키를 놓고 새로 선택하세요. 표시부만 다시 켜고 싶다면 전체 재부팅 대신 퀵 세팅의 위 길게를 사용하세요. 이 동작의 완료는 LCD·EVE 초기화 완료를 뜻하며 광원을 측정한 결과는 아닙니다.

## 롤백 후 새 업데이트
정상 CFW로 복귀했고 활성 기록·확정 작업이 없다면 이전 실패는 이력으로 남기고 새 ZIP을 선택할 수 있습니다. 이전 ZIP을 다시 고르거나 롤백 안내의 저장 완료를 기다릴 필요는 없습니다. 롤백 안내는 O를 짧게 눌렀다 놓으면 닫힙니다. 주기적인 상태 조회 때문에 같은 안내가 다시 열리지 않습니다.

실제 기록 작업이 남아 있거나 상태를 확인하지 못한 경우는 다릅니다. 앱은 현재 작업·경과 시간·차단 소유자를 확인하며 무조건 BUSY를 지우고 덮어쓰지 않습니다. 읽기 검사는 대기5초, 전체60초 상한이 있고 연결이 바뀐 응답은 폐기합니다. Bluetooth가 살아 있는 상태의 저장 정체를 재페어링으로 해결하려고 반복하지 않습니다.

## 설치 경로
새 Gate의 긴급 재부팅 기능을 확인한 기기는 일반 Product 업데이트를 사용합니다. 이전 Gate라면 앱이 안내하는 **데이터 유지 순정 복귀 → 새 Bootstrap → Gate·Product 설치**가 필요합니다. 일반 업데이트가 Gate를 몰래 덮어쓰지는 않습니다. 같은 릴리스의 APK와 ZIP을 함께 사용하세요.

## 이미 잠긴 구버전 기기
새 APK만 설치해서 구버전 본체의 멈춘 저장 작업이나 입력 코드를 교체할 수는 없습니다. 현재 상태 조회와 기존 복구 경로가 실제로 응답해야 이관할 수 있습니다. 그것마저 응답하지 않는 기기는 이 릴리스의 새 버튼 조작이 아직 들어가 있지 않으며, 본체 전원 재인가나 유선 복구가 필요할 수 있습니다. 현재 보고된 잠긴 실기기의 복구 성공은 확인하지 못했습니다.

이번 검증은 ARM 실행 시험과 EVE 소프트웨어 시뮬레이션입니다. 실제 LCD·무선 반복 설치 시험과는 구분합니다.
