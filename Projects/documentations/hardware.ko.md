# 하드웨어: 누도 모듈 안에는 무엇이 들어 있을까?

이 문서는 프로젝트에서 조사한 **AK 550 / SR1.5 계열 누도 모듈**을 설명한다. 순정 펌웨어에 특정 주변장치용 코드가 있다는 사실만으로 모든 연식의 보드에 그 부품이 실장됐거나 정상 동작한다고 결론내리지 않는다. 개발용 벤치 모듈에는 Bluetooth·조도 계통의 물리적 결함이 있다. 아래 내용은 [CubeIDE 설정](../STM32/FuckNudo_Noodoe_CFW_Project.ioc), 순정 코드 분석, 실측을 구별해 읽어야 한다. [English](hardware.md)

## 주요 데이터 경로

| 구성품 | 담당하는 일 | 확인 범위와 주의점 |
|---|---|---|
| STM32F429IE 계열 Cortex-M4F | 차량 정보 수신, 버튼·전원 상태 처리, Bluetooth 호스트 스택, 그래픽 명령 생성 | 프로젝트의 Cube 타깃은 STM32F429IET6이다. MCU 계열과 512KiB 내부 플래시 배치는 벡터·빌드와 일치하지만, 이 명칭을 모든 보드의 실장 칩 표기로 확대하지 않는다. |
| FT81x EVE | SPI로 받은 디스플레이 리스트·텍스처를 480×480 LCD에 렌더링 | STM32의 LTDC 전체 프레임버퍼 방식이 아니다. FT81x 계열까지 확인했으며 세부 모델 번호는 확정하지 않았다. |
| LCD·백라이트 | 원형으로 보이는 화면과 별도의 밝기 제어 | 실제 보이는 부분은 원형이다. 패널 제어와 TIM5 PWM 백라이트를 분리해 다룬다. 패널 제조사·품번은 확인되지 않았다. |
| 외장 NOR | 순정 FAT 파일, 사진·자산, 순정 업데이트 임시 공간, CFW 전용 파일 | 조사한 보드는 128MiB이며 4KiB 소거 블록을 사용한다. 다른 보드 리비전에는 재확인이 필요하다. |
| 외장 SDRAM | 이미지 디코딩, 자산 적재, 화면 캡처와 작업 버퍼 | 조사한 구성은 64MiB다. 휘발성 메모리이므로 전원 상실 후 파일처럼 보존되지 않는다. |
| TI CC256x | Classic Bluetooth 컨트롤러 | STM32가 HCI UART로 제어하고 SPP 호스트 프로토콜을 실행한다. 칩 리비전에 맞는 서비스 팩을 선택한다. 개발용 보드의 고장 부위를 칩 자체로 특정한 것은 아니다. |
| OPT3001 | 주변 조도를 측정해 자동 밝기 판단에 사용 | 레지스터·순정 코드 경로는 확인했지만 손상된 벤치 보드에서 정상 광응답을 확인하지 못했다. |

차량 계기판에서 넘어오는 정보와 IGN·버튼 신호는 STM32로 들어온다. STM32에서는 **SPI1→EVE→LCD**, **SPI5→외장 NOR**, **FMC→SDRAM**, **USART1→CC256x**, **I2C3→OPT3001**, **TIM5→백라이트 PWM** 경로가 각각 쓰인다. 화면이 480×480이라고 해서 MCU의 일반 SRAM에 480×480 전체 컬러 프레임을 쌓는 구조는 아니다. EVE의 디스플레이 리스트와 RAM_G가 실제 렌더링을 맡는다.

일반 SRAM은 192KiB, CCM은 64KiB로 취급한다. CCM은 CPU가 읽고 쓸 수 있지만 일반적인 DMA 목적지로 사용할 수 없다. 그래서 LVGL 메모리 풀은 CCM으로, UART·SPI DMA 버퍼와 태스크 스택은 일반 SRAM으로 배치한다. 정확한 주소와 예산은 [메모리 지도](memory-map.ko.md)를 참고한다.

## 버튼·전원·차량 연결

세 버튼은 MCU 기준으로 **위 PD12, 아래 PI6, 가운데/확인 PA15**다. 모두 누르면 LOW가 되는 입력이며, 에지 인터럽트만으로 조작을 확정하지 않고 시간 측정과 디바운스를 거친다. **PH9**는 별도의 계기판/누도 조작 선택 신호다. **PG13**은 조사한 회로에서 LOW가 IGN ON, HIGH가 IGN OFF인 상태 입력이다. 이 이름은 **MCU 핀 이름**이며 하네스 커넥터의 몇 번 접점인지를 뜻하지 않는다.

하네스 관찰에서는 12V 공급선 두 개, 버튼 관련 액티브 LOW 신호선 세 개, 5V 수준의 차량 UART 신호가 식별됐다. 커넥터 접점 전체와 MCU 핀을 일대일로 확정한 회로도는 아직 없다. IGN을 끄더라도 모듈의 상시 전원까지 모두 끊기는 것은 아니므로, 키 OFF를 곧바로 완전 전원 상실로 모델링하면 절전·복구 동작을 잘못 설계하게 된다.

벤치 모듈의 MCU 패키지 118·119번 다리 근처에서 떨어진 0402 부품이 발견됐다. 이것은 **개별 손상 보드의 관찰**이다. 부품값·원래 회로·Bluetooth 및 조도 결함과의 인과관계는 검증되지 않았다. 핀 번호가 비슷하다는 이유만으로 납땜으로 단락시키거나 정상 제품의 표준 회로처럼 취급할 수 없다.

## 확신 수준과 원자료

버튼·디스플레이·백라이트·차량 UART·NOR는 각각 별도의 브링업과 실측 기록이 있다. 반면 손상된 벤치 보드만으로 Bluetooth RF 성능이나 자동 밝기의 실차 동작을 보증하지 않는다. 펌웨어에 드라이버가 있다는 사실과 물리 장치가 정상이라는 사실은 서로 다르다.
