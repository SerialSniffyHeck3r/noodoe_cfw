# CFW 아키텍처: 무엇이 어디서 실행되나

이 펌웨어는 기능별 디렉터리만 나눈 것이 아니라 **고장났을 때 살아 있어야 할 부분**을 분리했다. 주행 UI가 외장 NOR의 임의 주소를 직접 지우거나, UI가 죽은 뒤에도 순정 복구가 UI에 의존하는 구조를 피하기 위해서다. MCU 소스는 [STM32CubeIDE 프로젝트](../STM32), 휴대전화 앱은 [Android 프로젝트](../Android)에 있다. 둘은 Classic Bluetooth SPP 위에서 프로젝트의 NDCP 메시지를 주고받는다. [English](architecture.md)

## 부팅 단계와 실행 주체

| 구성 | 실행 시점 | 책임 |
|---|---|---|
| 순정 상주 부트로더 | MCU 초기 부팅과 순정 APP 설치 | 순정이 제공하는 설치 경로. CFW는 이 영역을 일상적인 업데이트에서 교체하지 않는다. |
| Bootstrap | 최초 설치 때 순정 업데이터를 통해 진입 | 기기·부트로더 식별, SPP 세션, FAT 감사, CFW 파일 준비, 수신·물리 재읽기, 설치 승인 UI. |
| RecoveryGate | 정상적으로는 Product보다 먼저, 오류 때는 독립 복구 화면 | Product 이미지 검사·복사, 부팅 저널, 워치독, 버튼만으로 순정 APP 복원. |
| Product CFW | 실제 주행·휴대전화 연동 | 차량 상태, 화면, 설정, BT 통신, 자산·사진, 저장 요청과 시험 부팅의 건강 상태 보고. |
| 삭제·진단 전용 이미지 | 사용자가 명시적으로 선택한 임시 작업 | CFW 데이터 제거 또는 심층 주변장치 시험. 평소 주행 펌웨어와 구분한다. |

Gate는 내부 플래시의 독립된 64KiB 섹터에 있다. Product가 고장나도 Gate는 Product의 FreeRTOS·LVGL·외장 폰트·SDRAM·Bluetooth 없이 기본 EVE 도형과 ROM 글꼴로 화면을 낸다. Gate가 순정을 복구할 때 쓰는 정확한 순정 APP는 검증된 외장 NOR 파일에 보존한다. 그 파일은 순정 부트로더의 백업이 아니다.

## Product의 계층

**App_Logic**은 “이 값이 어떤 의미인가, 버튼을 누르면 무슨 상태로 가는가”를 소유한다. 주행/환경설정/전원이라는 큰 상태기계와 중앙 페이지별 작은 상태기계, 차량·정비·알림·트립 규칙이 여기에 속한다. 상위 코드는 레지스터 주소나 SPI 바이트 순서를 알 필요가 없다.

**Middlewares/Noodoe**는 작업을 제한된 크기의 큐와 비동기 상태로 처리한다. 차량 UART 프레임 파서, 버튼 이벤트, BT/NDCP, 조도·밝기 정책, 사진·자산 로딩, FAT 파일 소유권 검사, 설정·주행 저널, 업데이트와 건강 상태가 이 계층에 있다. 요청을 받았다는 응답과 NOR에 **영구 기록을 완료했다**는 응답은 다르다.

**Graphics/UI와 Graphics/Port**는 화면 모델을 원형 영역의 링·텍스트·이미지·애니메이션으로 만들고 EVE 디스플레이 리스트로 변환한다. 화면 전환 중에는 현재 표시 중인 텍스처를 다음 이미지 업로드가 덮어쓰지 않도록 수명과 swap 완료를 추적한다. 이는 간헐적 찢어짐을 막는 메모리 소유권 규칙이다.

**Drivers/BSP**는 MCU 핀, UART·SPI·I2C, EVE·LCD 초기화, 백라이트 PWM, NOR·SDRAM·워치독의 물리 접근을 맡는다. Cube가 재생성하는 Core 파일과 프로젝트 소유 코드를 나눴다. **Middlewares/Third_Party**에는 LVGL, FreeRTOS, BTstack 등 버전을 고정해 사용하는 외부 코드가 있으며 각 라이선스는 별도로 따른다.

## 주행과 휴대전화 데이터 흐름

차량 계기판에서 들어오는 UART의 속도·ODO·연료는 차량 모델이 해석한다. 바깥쪽 속도 링·시계·ODO가 공통 화면 골격이고 중앙의 트립, 음악, 전화, 알림, GPS 등은 선택된 페이지 모델이다. GPS 궤적은 휴대전화에서 받지만 차량 속도를 GPS 속도로 바꾸지는 않는다.

Android 서비스 하나가 Bluetooth 소켓과 송신 큐를 소유한다. 평소 주행 연동과 설치 작업은 별도 상태이며 설치 중에는 음악·알림·사진 전송이 설치 패킷을 방해하지 않도록 멈춘다. CJK 문자열이나 가변 폭 배치가 필요한 일부 텍스트는 휴대전화에서 이미지로 렌더링해 제한된 크기와 세대 번호·검증값을 붙여 보낸다. 구버전 CFW에 새 화면 형식을 무턱대고 보내지 않도록 기능 목록을 협상한다.

IGN OFF에서는 마지막 화면을 잠시 유지하고, 세션 종료가 확정되면 Ride Summary를 표시한다. 이후 설정된 **화면 유지·백라이트 OFF → 패널 OFF·Bluetooth 유지 → 완전 OFF** 단계를 따른다. 이때 LCD 구동, 백라이트 PWM, 무선 연결, MCU 수면은 같은 스위치 하나로 처리할 수 없는 별도 상태다.

## 실패를 가두는 경계

- 파일 수신이 끝나도 APP 설치가 아니다. 길이·대상·UID·벡터·필요 자산·해시와 NOR 물리 재읽기 결과를 확인한 뒤에만 부팅 저널을 바꾼다.
- Product 후보는 현재 코드에서 **30초간 정상적인 소유 태스크 진행**과 전화기·기기 간 버전 확인을 거쳐 확정된다. Bluetooth 소켓 연결만으로 정상 실행이 증명되지는 않는다.
- 저널 기록 중 전원이 꺼지면 이전의 완료된 기록을 사용한다. 복사 도중 종료됐으면 검증된 NOR 원본에서 다시 복사하고 반쯤 쓰인 APP를 실행하지 않는다.
- 이전 정상 Product를 NOR의 A/B에 보존한다. 반복 시험 부팅이 실패하면 Gate가 개입한다. 정상본까지 없거나 손상됐다면 자동 재부팅을 무한 반복하지 않고 복구 상태에 머문다.
- 워치독은 CPU가 건강 상태를 보고하지 못하면 재시작할 수 있게 하지만, 저장 완료나 사용자가 본 화면의 성공을 대신 증명하지 않는다.
