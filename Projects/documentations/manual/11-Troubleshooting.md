# 11. 문제 해결과 로그

[목차](README.md)

## 설치 화면이 안 움직일 때

앱의 **전체 단계 / 현재 작업 바이트 / 마지막 응답 / 최근 진행 변화 / 파일·섹터 위치**를 함께 확인합니다. 전송이 멈춘 것과 기기 내부 해시 계산·NOR 소거·순정 설치기 실행은 다릅니다. 총 퍼센트는 단계 기준이며 실제 남은 시간 비율이 아닙니다.

1. 기기 화면의 문구와 Help code를 기록합니다.
2. 폰에서 `응답이 끊긴 작업 확인` 등 문제 해결 마법사를 엽니다.
3. 같은 기기·같은 ZIP의 마지막 작업 상태부터 조회합니다.
4. `결과 미확인`이면 설치 성공/실패 어느 쪽으로도 임의 확정하지 않습니다.
5. 진단 자료를 내보내고, 필요하면 본체 Gate/Bootstrap의 Back to stock을 사용합니다.

## 자주 만나는 증상

| 증상 | 확인할 것 |
|---|---|
| Bootstrap 전송 후 자동 연결 지연 | Android 페어링 요청을 승인했는지, 같은 주소인지. 이미 도구가 올라갔다면 연결 확인만 먼저 실행 |
| `NOODOE INSTALLER` | 설치 중. `CFW UPDATE`와 다름. 전송을 다시 시작하거나 완료 확인하지 않음 |
| `Checking the new version` / `CFW UPDATE` | 폰 앱에서 실제 화면 확인 → 같은 후보 재연결 → 30초 건강 확인. 180초 기한 안에 진행 |
| 순정인데 앱은 WAIT_CFW_BOOT | `본체에서 순정으로 돌아왔어요 · 확인`. 실제 순정 응답을 읽어 기존 작업을 해소 |
| `STOCK_RETURN_CONFIRMED` | 순정 복귀 완료 기록. 새 APK의 재설치 마법사로 새 시도 생성; 기록 삭제로 우회하지 않음 |
| `00050006` | 저장소 형식/내용 검사 실패 계열. 파일 번호·phase·offset과 함께 기록. 특히 file 3 / phase 9.2는 사진 컨테이너 검사 문맥. 코드만 보고 무조건 포맷하지 않음 |
| `Update wasn't confirmed` | 후보 실행 확인 실패. 이전 정상본 롤백 또는 Gate 복구. 파일 전송 실패와 동일하지 않음 |
| 버튼이 안 됨 | 계기판 조작 스위치의 왼쪽 파란 아이콘, 눌린 채 진입했는지, 정차/권한 제한 확인 |
| GPS Waiting | 정밀 위치·서비스·IGN·연결·수신 환경 확인. 강제 종료된 앱은 다시 실행 |
| 곡/아트가 늦음 | 알림 접근, 활성 MediaSession, 플레이어의 메타데이터 제공, OS 백그라운드 제한 확인 |
| 전화 Permission Denied | 연락처/통화기록/발신/동반 통화 제어는 별도 승인. 해당 권한을 확인 |
| 조도/Storage error | 실제 오류 코드·마지막 저장 성공 상태 확인. 정상 동작해 보인다고 저장 성공을 가정하지 않음 |
| ODO* | 사용자가 저장 ODO 기준 유지를 선택한 보정 표시. 차량 계기판 원본 변경이 아님 |

## 연결·설치 상태 초기화

앱의 문제 해결 영역에서 실행합니다. 소켓·선택 기기/ZIP·임시 UI 상태를 정리하고 기기 선택으로 돌아갑니다. **본체 ABORT/RESET을 자동 전송하지 않으며 본체 작업을 취소한 것으로 표시하지 않습니다.**

기존 로그·설치 저널·원본 백업·다운로드 ZIP·Android 페어링·앱 테마·사용자 설정은 지우지 않습니다. 같은 기기에 결과 미확인 작업이 남으면 재연결 후 먼저 조회합니다. 실제 호환성 불일치나 불명확한 확정을 우회하는 버튼이 아닙니다.

## 진단 자료 공유

`진단 자료 공유`로 ZIP을 저장하거나 공유합니다. 폰 내부 원본 로그는 그대로 남습니다. 연결 세대, 기기/패키지 식별, 명령·검증 위치, 재연결·부팅·롤백 결과를 분석하는 데 사용합니다. 일반 로그에는 알림 본문·음악 제목·정밀 좌표·페어링 비밀키를 기록하지 않습니다.

일반 이벤트 로그는 크기 제한을 두고 순환하며 복구 증거와 미해결 실패 기록은 별도로 보존합니다. 설치 중 저장소 부족 등으로 필수 저널을 쓸 수 없으면 작업이 중단될 수 있습니다. 폰의 저장 공간도 확인하세요.

USB debugging 사용자는 개발 진단 APK의 `adb shell run-as io.noodoe.installer`로 앱 내부 파일에 접근할 수 있습니다. 일반 APK에서는 앱에서 Downloads에 내보낸 ZIP을 `adb pull`로 가져옵니다. 디버깅 가능 여부는 APK 빌드 종류에 따라 다르며 설명서 링크가 이를 바꾸지는 않습니다.

문제 제보에는 **APK/CFW 버전, 기기 화면 문구와 코드, 발생 단계, 누른 버튼, IGN 상태, 마지막 파일·섹터 위치, 진단 ZIP**을 함께 제공하세요. 민감한 내용은 공개 게시물에 그대로 올리지 마세요.
