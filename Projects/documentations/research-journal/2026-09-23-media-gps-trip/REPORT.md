# 2026-09-23 미디어·GPS·30초 설치 확인

Companion6.8.0과 대응 Product를 빌드하고 연결된 벤치에 설치했다. 실제 EVE 화면을 캡처하고 GitHub Latest 및 README 다운로드 링크를 갱신했다. OpenNoodoe 원본·Cube 생성 파일·vendor JPEG 디코더는 수정하지 않았다.

## 추가 명세

* 앱 꾸미기 메뉴의 ‘테스트 알림 보내기’는 Android 로컬 알림을 실제 NotificationListener로 수집한다. 정확한 자체 테스트 태그/ID만 허용 목록 예외로 인정한다. 알림 접근·표시 권한과 채널 비활성 상태를 안내한다. CJK를 렌더링해 기존 SPP 큐로 보내며 다른 사람에게 메시지를 전송하지 않는다.
* `Health_Service.h`와 `gate_abi.h`의 정상 실행 기준을30000ms로 통일하고 Product에서 정적 일치 검사를 한다. BT 준비·앱의 후보 버전 확인·영구 저널 완료 조건은 유지한다. 3분 미확정 롤백 기한과 워치독 고장 검출 조건은 변경하지 않았다.
* `BootReconnectPolicy`는 업데이트 후 최대5회,5/8/12/15/20초 간격으로 연결을 재시도한다. 연결 후 상태 조회와 확인만 수행한다. COMMIT/RESET을 맹목적으로 반복하지 않는다. 진행 문구와 Product 확인 화면을 간결하게 변경했다.
* `Bluetooth_NameSuffix()`는 컨트롤러의 실제 주소[3..5]를 대문자16진수로 표시한다. `98:07:2D:01:71:0F`이면 `FuckNudo CFW 01710F`. Bootstrap과 Product가 같은 저수준 코드를 쓴다. 주소·키·프로토콜 역할 식별자는 바꾸지 않는다.

## 영상·주행 표시

현재 tjpgd의 JPEG 출력 타일은 BGR565였다. `PhotoJpeg_CopyRGB565()`로 빨강/파랑5비트만 교환하고 녹색6비트를 보존해 사진/앨범 아트 공용 경로를 수정했다. 알려진 색 JPEG의 실제 ARM 디코드 시험과 벤치의 이전/이후 캡처에서 확인했다.

폰 아트는480×480, 최대48KiB JPEG로 처리한다. 임시 아트와 CJK 제목 키를 분리하고, 알림 이미지보다 음악 전송을 우선한다. URI 로딩은 단일 비동기 작업이며 읽기 상한4MiB, 디코드 크기는960px 이하이다. 늦게 도착한 이전 곡의 결과를 새 곡으로 사용하지 않는다. 실제 무선 지연 감소 시간은 이 벤치에서 측정하지 않았다.

음악 시간은4px 아래로, 버튼 힌트는2px 왼쪽으로 이동했다. 속도 링의 바깥 반경240을 유지하며 폭18→20px로 변경했다. 오일 잔량 호는중심X240, 중심선의 최하단Y458.5, 폭9px, 각도73°..107°이다. BELT/SERV의 DAYS는 숨기고 날짜·시간 수명 계산은 유지했다.

GPS는 긴O로 북쪽/진행 방향 고정, UP/DOWN으로6단계 줌을 선택한다. 50px 축척은20/50/100/200/500/1000m이다. 유효한 위치에서 대기 문구를 숨긴다. 359→0 방향은 단위 벡터로 보간하고 정차 흔들림·오래된 시간·고립된 점프를 처리한다. 큰 수/날짜변경선을 먼저 정수로 계산한 후 M4F로 투영하며, 실제 FPU를 활성화한 ARM 시험을 수행했다.

트립 보정은 연속된 ODO1km 구간에서 계수를 학습한다. 최초 불완전 구간·통신 공백·역행·비정상 ODO 점프를 제외하고 이후 적분에만 적용한다. 보고된13.6/14.4 비율을 하드코딩하거나 과거 누계를 재작성하지 않았다. 계수는 현재 실행 중 유지하며 재부팅 후 다시 학습한다. Ride Summary도 같은 계수를 사용한다. 실제 도로 비교는 남아 있다.

## 실제 기기 검증

* UID `0039001f 3436510f 35373339`의 기존512KiB 내부 이미지를 보존했다.
* 비활성 CFW NOR 슬롯과 다음 부팅 저널 섹터만 변경했다. 기존 활성본·자산을 남기고 섹터마다 원본/변경/실제 읽기 결과를 기록했다.
* Product를0x08020000에 설치하고 내부 전체 플래시를 두 번 읽어 대조했다. 순정 하위64KiB·현재 Gate·FAT는 동일했다. `bench-write-evidence-*/result.json`과 각 섹터 기록을 보존했다.
* `after.png`, `after-music.png`, `after-gps-north.png`, `after-gps-heading-zoom.png`, `after-belt.png`, `after-oil.png`, `after-light.png`는 실제 EVE 캡처다. LCD 유리 촬영이나 폰의 RF 전송 성공을 의미하지 않는다.
* 미디어/GPS만 일시적인 RAM 데이터로 주입했다. 실제 JPEG CRC·디코드 작업과 렌더러를 실행했다. 시험 후 원래 상태를 복원했으며 UART 속도·주행 누계·NOR 사진은 변경하지 않았다.
* FPS·CPU·힙·CCM·오류 상태는 `performance.json`, `after-light-status.json`에 기록했다. 캡처 중 정지 시간과 평상시 렌더링 성능은 구분한다.

Android202개 시험과 lint 오류0건, GPS/트립6개 빌드 조합, 전원 상태1155개 검사항목×2, 실제 JPEG/PhoneVisual2개 ARM 시나리오, trial boot8개 시나리오, BT 전송/이름, Gate 확인 경계/복원, Bootstrap UI와 호10,000개 끝점 시험을 통과했다. 기존 lint 경고82건은 모두 해결했다고 주장하지 않는다.

Gate·순정 복구본·외장 자산·삭제 전용 바이너리는6.7.0 배포본과 동일하다. 현재 벤치의 기존 BT 하드웨어 장애 때문에 새 이름의 실제 RF 검색·5회 재접속·폰에서의 알림 수신·무선 전송 시간은 정상 무선 기기에서 추가 확인해야 한다. 로컬 SWD 설치를 무선 시험 부팅 확정으로 간주하지 않았다.
