# 설치·업데이트·순정 복구

설치기의 기준은 **주행용 Product 또는 Bluetooth가 고장나더라도 사용자가 돌아올 길이 남아 있어야 한다**는 것이다. 아무 STM32에나 쓸 수 있는 범용 플래셔가 아니다. 기기 모델·보드·부트로더·순정 복구 이미지가 맞아야 한다. 실제 차량에 쓰기 전에는 해당 릴리스에 적힌 대상과 검증 범위를 확인해야 한다. [English](installer.md)

## 최초 설치: 순정에서 CFW로

1. Android 설치 마법사가 선택한 누도와 패키지를 식별한다. 순정 APP가 제공하는 업데이트 경로로 작은 Bootstrap을 전송한다. 휴대전화가 순정 부트로더나 임의 MCU 주소를 직접 쓰지 않는다.
2. Bootstrap이 보드·BL 식별값과 FAT 할당 상태를 조사한다. CFW가 새로 사용할 빈 클러스터, 두 FAT 사본, 순정 업데이트 예약 공간과 다른 파일의 소유권을 확인한다. 앱은 변경 명령에 앞서 세션·패키지·기기 식별과 복구 증거를 로컬 저널에 남긴다.
3. 검증된 범위 안에 CFW 전용 파일과 순정 APP 복원본을 준비한다. Product 본체는 한 번 수신하고, 필요한 복사본은 가능한 한 기기 안에서 만든다. 파일을 썼다는 응답과 실제 NOR에서 재읽어 무결성을 확인했다는 응답은 구분한다.
4. 기기에서 설치를 확정하면 기존 순정 설치 경로가 Gate와 Product를 내부 플래시에 배치한다. 전송 100%는 이 단계의 완료를 뜻하지 않는다.
5. 새 Product의 첫 부팅은 **시험 부팅**이다. 현재 코드 기준 30초 동안 필수 태스크가 정상 진행하고 서비스가 올라와야 하며, 앱도 같은 기기 UID와 후보 버전을 확인해야 정상본으로 확정한다. 후보 확인 전에는 이전 정상 CFW가 있다면 그것을 보존한다.

순정 부트로더가 자체적으로 플래시와 메타데이터를 다루는 최초 설치 구간은 CFW Gate로 소급해서 원자적으로 만들 수 없다. 그래서 최초 설치는 일반 Product 업데이트와 위험 경계가 다르다. “Bluetooth 연결됨”, “파일 수신됨”, “새 버전 화면 표시됨”, “영구 확정됨”을 앱과 기기 화면에서 한 사건처럼 표현하면 안 된다.

## CFW가 이미 설치된 뒤의 업데이트

Gate와 자산 형식이 같으면 일상 업데이트는 기본적으로 **384KiB Product APP**만 비활성 NOR A/B 파일로 보낸다. Gate·순정 복구본·FAT 구조 전체를 매번 다시 만들지 않는다. 수신기는 대상과 UID, 헤더·벡터, 필요한 자산, 길이·해시, NOR 물리 재읽기를 확인한 뒤 후보를 저널에 등록한다. Gate는 검증된 후보를 내부 0x08020000–0x0807FFFF로 복사하고 내부 플래시도 다시 확인한다.

전송이 끊기면 앱은 확인된 섹터·오프셋과 패키지 해시를 기기에서 다시 조회해 이어 보낸다. COMMIT·RESET 요청의 응답이 유실되면 결과가 불확실한 것이므로 상태를 먼저 조회한다. 같은 명령을 무조건 다시 보내지 않는다. 새 실행본의 건강 상태 또는 전화기 확인이 실패하면 이전 정상 Product가 보존돼 있을 때 Gate가 그 이미지로 돌아갈 수 있다. **CFW 내부 롤백**과 **순정으로 복귀**는 별도 결과다.

Gate 자체, Bootstrap 또는 자산 파일 형식을 바꾸는 릴리스는 단순 Product 업데이트에 몰래 섞지 않는다. 그 경우 릴리스가 별도 이관 절차를 안내한다. 첫 CFW 설치에는 당연히 “이전 정상 CFW”가 없으므로 롤백할 것이 없다는 사실도 표시해야 한다.

## 버튼으로 순정 복구

RecoveryGate는 내부의 독립 64KiB 섹터에 있고 Product, Bluetooth, SDRAM, LVGL, 외장 폰트에 의존하지 않는다. 기본 EVE ROM 글꼴·도형으로 복구 화면을 그리며 워치독을 사용한다. 조사한 배선에서 의도적인 진입 제스처는 **키 OFF → 가운데 O를 누른 채 키 ON → 정해진 시간까지 계속 유지**다. 진입 자체가 Product를 지우거나 순정 설치를 승인하는 것은 아니다. Gate 화면에서 버튼을 떼었다가 새로 눌러 복원을 확정한다.

Gate는 CFWREC.DAT의 순정 APP를 해당 버전·보드 식별·보존된 부트 코드 정보와 대조한다. 확인된 이미지를 순정 업데이트 임시 공간에 기록·재읽기 검증한 다음 순정 설치기로 인계한다. **긴급 버튼 복구는 CFW 파일을 지우지 않는 데이터 유지 경로**다. 그래서 순정 사진과 원래 파일은 보존되고, CFW가 추가한 파일은 NOR에 남는다. 파일의 실제 내용을 지우고 FAT 할당 공간까지 되돌리는 것은 별도의 삭제 전용 경로다.

CFW와 무선이 모두 죽어도 Gate·버튼·MCU·NOR·순정 설치기가 정상이고 복구 이미지가 보존됐다면 이 경로가 ST-LINK 없이 돌아올 방법이다. 그러나 물리적으로 손상된 NOR, 잃어버린 순정 이미지, 망가진 전원·클록 또는 순정 상주 부트로더까지 복구한다고 말할 수는 없다. 디버그 포트에 접근하기 어려운 실차에서는 이 한계를 설치 전에 이해해야 한다.

## 무엇을 보존하는가

순정의 MAC·PIN·차량 식별 같은 공장 데이터는 사용자 환경설정이 아니다. Product 업데이트와 일반 순정 복원은 하위 내부 부트·공장 영역을 의도적으로 교체하지 않는다. CFW의 설정·트립·사진 3장·로그·자산·A/B 이미지는 검증된 별도 FAT 파일에 놓는다. 순정 APP 복귀 후 순정 사진과 파일이 보이는 것이 정상이며, CFW 파일을 남겼다고 해서 모든 외장 NOR 바이트가 공장 출고 상태와 완전히 같아진 것은 아니다. 전화기의 Bluetooth 결합키가 달라졌다면 별도로 재페어링이 필요할 수 있다.

화면별 단계는 [사용 설명서](manual/08-First-Install.md)에, 전송 규격은 [NDCP 기술 노트](technical-notes/ndcp-protocol.md)에, 저널·상태 계약은 [설치 세션 문서](technical-notes/install-session-v2.md)에 있다. 각 릴리스는 여기 적은 **설계**와 별개로 실제 어떤 보드에서 중단·복구 시험을 했는지 밝혀야 한다.
