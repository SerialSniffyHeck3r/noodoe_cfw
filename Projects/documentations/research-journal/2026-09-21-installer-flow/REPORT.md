# Bootstrap 설치 계속 / 설치 후 CFW 업데이트

## 현재 기기에서 사용할 순서

1. `NoodoeInstaller-flow.apk`를 기존 앱 위에 설치한다. 앱 데이터를 삭제하지 않는다.
2. 현재 Bootstrap을 올릴 때 사용했던 **기존 ZIP**을 그대로 선택한다. 기기의 Bootstrap SHA와 일치해야 한다.
3. `3. 설치도구 → CFW 설치 계속`을 누른다. 별도 연결 확인 작업은 필요 없다.
4. Bluetooth test 화면이라면 O로 돌아가 `Install CFW`를 선택하고 O를 누른다. 키 ON과 상시 전원을 유지한다. 폰은 같은 연결에서 선택·인증·시작 검사가 끝나기를 기다린다.
5. 복구 자료 보관·파일 준비·전송 뒤 기기에서 최종 Install CFW를 선택한다. 재부팅 후 정상 실행·영구 확정까지 폰이 확인한다.

현재 기기용으로 새 ZIP을 무작정 선택하지 않는다. 이 폴더의 `vehicle015/installer.zip`에는 화면 흔들림까지 수정한 **새 Bootstrap**이 들어 있다. 새로 순정에서 시작하는 설치용이며, 현재 구 Bootstrap과 SHA가 다르다. 새 APK는 기존 ZIP과 새 ZIP을 모두 검사할 수 있다. SHA 대조는 유지한다.

## 고친 원인

- 연결 확인은 진단만 한 뒤 소켓을 닫았다. 최초 설치가 다른 연결에서 시작되어 로컬 설치 선택과 연결 세대의 인증이 끊겼다. 새 흐름은 실제 identity 대조 → 같은 세션의 설치 메뉴 선택/보안/저장소 준비 읽기 확인 → 준비/전송/확정을 연결한다.
- 이미 Bootstrap이 실행 중인데 ZIP을 새로 선택하면 IMPORTED 기록에서 준비 단계로 넘어갈 수 없었다. 실제 UID/BL/Bootstrap SHA 검증 뒤에만 이 기록을 식별 완료로 승격한다.
- 부팅 직후 9파일 검사 동안 하위 64KiB 읽기가 명시적으로 BUSY를 반환할 수 있었다. 읽기에 한해 제한 시간 내 BUSY를 기다린다. 쓰기나 결과 불명확 명령은 반복하지 않는다.
- 이전 앱은 첫 백업 읽기 전에 BACKUP_IN_PROGRESS를 기록했다. 인증 거절 이후 그 상태로 막힐 수 있었다. CREATE_BEGIN 의도가 전혀 없는 읽기 전용 준비 단계에 한해 이전 증거 경로를 보존하고 새 읽기 계획을 만든다. CREATE/FILE_CREATED/COMMIT 불명확 기록은 초기화하지 않는다.
- 기기 화면이 작업 소유권 대신 매 파일의 busy 변화를 따라 바뀌었다. 9파일 시작 검사는 하나의 CHECK 화면으로, 사용자 설치는 파일 간 대기까지 하나의 설치 화면으로 유지한다. BT 시험 메뉴도 배경 검사 때문에 교체되지 않는다. 설치 메뉴가 기본 선택이고 최종 설치 확인은 계속 Back 기본값이다.

실제 사용자의 폰 로그를 가져온 것은 아니므로 위 경로 중 어떤 것이 이번 현장에서 발생했는지는 아직 확정하지 않았다. 재현 가능한 코드 결함과 보고된 증상에 대응하는 경로를 수정했다.

## 설치 후 업데이트

메인 화면의 `새 CFW로 업데이트 / 전송 이어가기`를 사용한다. 기존 RoutineUpdateSession을 유지하면서 일반 설치와 분리해 노출했다.

- 같은 RecoveryGate를 확인하고 Product APP 384KiB만 전송한다. Gate와 순정 BL을 다시 쓰지 않는다.
- 현재 실행의 정상 확정 전에는 다른 업데이트를 시작하지 않는다. 이미 후보 SHA가 실행 중이면 재전송하지 않고 기존 정상 부팅 확인으로 연결한다.
- 4KiB 검증 완료 경계에서 재개한다. COMMIT 응답이 사라지면 원격 상태를 먼저 확인하고 동일 COMMIT을 반복하지 않는다.
- 재부팅 후 기존 60초 정상 실행·BT 초기화·앱 확인·영구 확정 정책과 실패 롤백을 유지한다. 파일 전송 완료를 설치 성공으로 표시하지 않는다.
- 동일 Gate와 호환 자산을 전제로 한다. 새 자산/다른 Gate가 필요한 패키지를 이 경로로 무조건 설치하지 않는다.

## 검증

- Android 111개 단위시험, APK 빌드 통과. 설치 메뉴 대기/거절/단절, 읽기 전용 준비 재시작, startup BUSY, Product 전체 전송/섹터 재개/COMMIT 응답 유실/중복 방지/미확정 부팅/다른 Gate 거부를 포함한다.
- 실제 ARM C를 Unicorn에서 실행한 UI·버스·취소·확인·제스처 44경우 통과(O0/Os). 9파일 검사와 각 파일 사이 100회 대기에서 루트 메뉴로 복귀하지 않는 것을 검사했다.
- 새 ZIP과 직전 status ZIP을 실제 Java importer로 검증했다.
- Bootstrap 443,500B, 여유 15,252B. Product ELF는 변경 없이 재사용하고 패키저에서 예산 재검증: Release 여유 67,200B, Debug 여유 33,584B. 이번 턴 Product 재빌드/플래시는 하지 않았다.
- 실제 폰 화면, RF 전송, 버튼 입력, 전원 중단 및 복구는 이번 턴 미검증이다. APK와 새 Bootstrap은 장치에 설치하지 않았다. 호스트 시험을 실차 설치 성공으로 간주하지 않는다.

정확한 산출물 SHA와 시험 원본은 `verification-summary.json`, `test-results`, 빌드 로그에 있다. OpenNoodoe 원본·Cube 생성 코드·순정 BL·메모리 예산은 변경하지 않았다.
