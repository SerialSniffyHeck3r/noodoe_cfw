# 0.9.42 validation — render cadence, GPS and parked input

## Outcome

The code paths that blocked parked O, hid simultaneous held keys and gated
synthetic GPS on the real location service were corrected. A four-second GPS
sample interval no longer alternates into a three-second stale timeout.
EVE SPI overhead and the largest cooperative map slice were reduced.

**The target remains 30fps. Physical 30fps, elimination of the owner's observed
LCD stutter/tearing and real wireless behavior have not been measured here.**
The reported physical 10fps condition was not reproduced on a bench. The
software evidence below does not establish its complete real-world cause.

## Changes and evidence

- EVE exchange uses dedicated SPI1 full-duplex byte handling. One outstanding
  byte, RX draining, final TXE/BSY completion, finite timeout/error propagation
  and the existing CS policy remain. No SPI clock increase, interrupt masking
  or DMA-resource reassignment. Two 256-byte dummy buffers are removed.
- The actual ARM SPI model passed 36 cases: send/read lengths 1, 4, 255, 256,
  257, 4092 and 8192; RX/TX/BSY stalls; OVR/MODF/FRE; and injected preemption.
  At 8192 bytes, write-path instructions fell from 989,876 to 747,927 (24.4%).
  A simplified 168MHz/21MHz, one-cycle-per-instruction model gives 5.8921ms
  versus 4.4519ms. These are comparative model values, **not measured MCU time**.
- Map work previously computed/uploaded up to 32 rows (15,360 bytes) at once.
  It now yields after eight rows or a 2ms check between rows, with at most
  3,840 bytes per upload. One row plus its upload can extend beyond 2ms.
  Injecting 1ms per clock query reduced the slice to two rows/960 bytes. Both
  schedules produced the same complete raster hash:
  `395f27ebcd9022767ab607fa40af2f5345ae10d8583aa2a71fe213cbf134b535`.
- Finite squared distances use M4 `vsqrt.f32` directly instead of the libm
  error/domain wrapper per covered pixel. The compactor initializes its root
  context only and uses an opcode-class mask. SAVE copies initialized state.
  The compass and trail share atan2f rather than separate heading approximations;
  the previous approximately 0.3-degree approximation is no longer duplicated.
- Android permits synthetic GPS without real location permission/location FGS.
  Real providers retain those requirements; active riding or explicit parked use,
  Bluetooth connectivity and map import/settings remain required. Map errors are
  visible alongside the test-mode notice.
- Firmware and phone use a five-second fix freshness window. Actual expiry,
  reacquisition, duplicate accepted samples, rejected old samples and tick wrap
  passed 1,827 assertions each at O0 and Os. Duplicate snapshots do not refresh
  fix age or append trail points.
- OFF+O only arms a future Gate entry; arming alone no longer blocks ordinary
  parked-use O. The actual ON-held confirmation still owns input. Filtered chord
  edges update physical key feedback exactly once, while normalized actions and
  their context cancellation remain separate.

The first full Android attempt had 16 failures: disk pressure affected NOR
fixtures and three old UI tests still assumed the pre-0.9.41 busy/pending model.
The tests now supply the real workflow owner and durable install journal.
A two-image FAT test releases each synthetic file after its subcase. Production
installer and backup behavior was not changed to make these tests pass.
All initial failed cases were required to pass recorded isolated reruns; GPS,
map feed and test-dialog suites were also rerun. This is an aggregate of recorded
runs, not a claim that the first full run passed.

The old Monaco bitmap `NavigationTest` fixture was unavailable and that one
test was skipped. The current Korea vector-map integration test passed with
the actual regional map file. The skipped test is not counted as passing.

One older `dashboard_pages` harness still feeds raw RELEASE events directly to
UiState and fails its navigation assertion at line271; it predates the normalized
InputRoute contract. It is not counted as passing. The current Product UI,
10,000-sequence input integration and full-frame harnesses exercise that contract.
The old `eve_state_host` extractor remains outside this validation because it
references a previously removed bitmap-seeding block.

## Memory and compatibility

| Product | 0.9.41 flash used B | 0.9.42 flash used B | Free flash B | Free SRAM B |
|---|---:|---:|---:|---:|
| Debug | 391,064 | 391,160 | 2,056 | 45,560 |
| Release | 358,900 | 359,060 | 34,156 | 44,592 |

Debug retains 2,056 bytes: only eight bytes above the requested 2,048-byte hard
minimum. Release retains 34,156 bytes, above its 4,096-byte minimum. Both retain
16,320 bytes free CCM; fixed SDRAM/GPU buffers, heap/stack reservations and
compiler policies are unchanged. Fonts and required resource bytes are unchanged.

Bootstrap is 445,316 bytes with 13,436
bytes free and uses the shared SPI implementation. Its Bluetooth policy remains
921,600 baud. Gate is byte-identical to 0.9.41 (23,588 bytes, features15).
Product retains its existing high-speed Bluetooth policy. No pairing, storage
journal, Gate partition or photo/service-record format changes are included.

Use matching 0.9.42 APK/ZIP. Compatible 0.9.40+ Gate installations use normal
Product update. The existing explicit keep-data migration is retained for older
Gate versions; ordinary updates do not replace Gate.

## 한국어

주차 사용 중 O가 차단된 이유는 키 OFF에서 O를 누르기만 해도, 다음 키 ON을
위한 복구 준비 상태가 일반 입력을 잡았기 때문이다. 실제 ON 유지 확인 때만
입력을 점유하도록 수정했다. 두 버튼 표시가 안 된 것은 조합 입력을 소비할
때 물리 눌림까지 지웠기 때문이며, 조작 실행과 눌림 표시를 분리했다.

GPS는 4초 간격으로 수신되는 위치가 기기의 3초 기준에서 끊기는 조건을
재현해 5초로 맞췄다. 테스트 좌표가 실제 위치 서비스 준비 여부에 막히는
앱 경로도 고쳤다. 실제 한국 지도 데이터와 펌웨어 디코더·LVGL·EVE로 서울
지도를 캡처했다. 그림은 실기 사진이 아닌 **EVE 소프트웨어 시뮬레이션**이다.

SPI 비용과 지도 계산의 연속 점유 시간을 줄였으나 실기 30fps를 측정한 것은
아니다. LCD 프레임률·무선 상태·소비전력과 실제 찢어짐 재발 여부는 별도로
확인해야 한다. 이 보고서에서 그 결과를 성공으로 대신 처리하지 않는다.
