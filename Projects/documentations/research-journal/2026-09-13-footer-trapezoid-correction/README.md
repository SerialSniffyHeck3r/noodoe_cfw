# 키로수칸 위 사다리꼴 복원 — 2026-09-13

사용자의 '아래만 직선'을 위·아래 모두 직선으로 잘못 적용한 부분을 바로잡았다.

## 최종 좌표

- 시계 구분선: (148,77)→(172,96)→(308,96)→(332,77), 기존 모양·위치 유지.
- 키로수칸 위: (92,420)→(116,401)→(364,401)→(388,420), 사다리꼴 복원.
- 키로수칸 아래: (144,448)→(336,448), 직선 유지·길이 212→192px.
- 세 구분선 모두 `SPEED_HOME_SEPARATOR_STROKE=3`: 기존보다 1px 두껍다.
- 오일 잔량바: x160/y454/160×6px. 가운데 정렬을 유지하면서 184→160px로 줄였다.

거리 영역의 Y401..448 간격과 모든 글자·아이콘·단위 위치/크기는 유지한다.
HOURS는 계속 숨기고, 실제 IGN 시간 계산과 BELT/SERV의 DAYS는 유지한다.
APP 로직·상태머신·포맷팅 소스의 해시는 앞서 통과한 ARM 테스트와 동일하다
(`logic-preserved.json`). Cube 생성 코드와 BSP/미들웨어는 변경하지 않았다.

## 장치 검증

첫 설치는 기록 검증·재부팅이 정상 통과했으나, `preview/`의 실제 픽셀 검사에서
수평선의 유효 두께가 여전히 약 1.90px인 것을 발견했다. 기대값을 완화하거나
캡처를 편집하지 않고 원인을 조사했다. 현재 LVGL EVE의 수평/수직 RECTS 분기는
LINE_WIDTH를 설정하지 않는다. 또한 `lv_line`은 첫 구간 이후 round_start를
지우므로 다중 점 선에 line_rounded만 설정하는 것으로는 충분하지 않다.

최종 구현은 각 구간을 두 점짜리 lv_line으로 만들고 양 끝을 둥글게 설정한다.
EVE는 모든 구간에서 지정한 폭을 적용하는 LINE_STRIP 경로를 사용한다.
두 사다리꼴 6구간과 아래 직선 1구간, 총 7개 객체를 초기화 때만 생성한다.
LVGL 원본은 그대로 유지하며 이후 값 갱신에 새 할당을 추가하지 않는다.
실패한 첫 캡처는 `preview/`에 보존하고 최종 결과는 `preview-final/`에 기록한다.

이전 턴의 100kHz 기록 불일치를 고려하여 이번 APP 쓰기는 50kHz,
독립 읽기는 이미 검증한 950kHz를 사용한다. 하위 64KiB는 보존하며,
APP 전체 읽기 대조와 순정 BL을 통한 재부팅을 확인한 뒤 화면을 검사한다.
최종 `install-final/summary.json`은 pass다. CubeProgrammer 기록 검증과 독립
APP 전체 대조, 하위 64KiB 보존, 두 번의 순정 BL 재부팅 및 HAL/RTOS 진행이
통과했다. 디버그 동결 설정도 설치 전 값으로 복원했다.

최종 `preview-final/results.json`의 세 화면이 모두 통과했다.

- OIL 20%: 짧은 잔량바가 표시되고 HOURS는 계속 숨겨짐.
- BELT: 기존 DAYS와 거리·단위 배치 유지.
- ODO 75%: 전체 화면에서 위 사다리꼴·아래 직선·짧은 잔량바를 확인.

시계 및 위·아래 거리 구분선의 수평부 RGB565 색상 적분은 모두 약 2.925px
상당이었다. 기존 2px 경로의 약 1.896px와 구분되며, 양자화·안티앨리어싱을
포함하는 실제 3px 경로 기준을 통과했다. 숫자와 단위의 실제 하단은 y436으로
유지됐다. 캡처 시점 HUD는 29.9 FPS, CPU 58.0%였다.

이 결과를 시간 누계의 영구 저장 성공으로 해석하지 않는다.
