## 표시 변경

키로수칸 위·아래의 사다리꼴을 짧은 직선으로 바꿨다. 시계 구분선은 유지했다.
위 선은 (126,401)→(354,401), 아래 선은 (134,448)→(346,448), 두께는 2px다.
이전 가로 구간보다 각각 20px·16px 짧으며, 위로 2px·아래로 2px 확장해
키로수칸 세로 간격을 43px에서 47px로 넓혔다. 글자·아이콘의 위치와 크기는 같다.

오일 잔량바는 x148/y454/184×6px다. 기존 190×4px보다 조금 짧고 두껍다.
고정된 전체 트랙 안에서 잔여율 0..1000에 따라 왼쪽부터 채운다. 이전의 유효성,
0%·미확인 트랙 색상, 20% 이하 주황·그 위 청록색 기준을 유지한다.

OIL의 HOURS 글자와 시간 숫자는 화면에서 제거했다. OIL에서도 오일 잔량바를
표시한다. IGN ON 시간 계측·정비 수명 계산·저장 계약은 유지한다. 프레젠터는
HOURS를 내부 데이터로 계속 갖고 있지만 뷰는 해당 문자열을 표시하지 않는다.
시간과 잔량의 유효성은 독립적이다. BELT/SERV의 DAYS 표시와 계산은 유지했다.

## 실제 장치 기록

최초 APP 설치 후 CubeProgrammer 검증에서 0x0803861E가 예상 0x49 대신 0x91로
읽혔다. APP 전체를 독립적으로 두 번 읽어도 같은 한 바이트만 달랐다.
하위 64KiB는 보존됐고 CPU를 실행시키지 않은 채 실패 기록을 보존했다.
`install/`, `recovery-read/`를 참조한다. 이는 이전 턴의 일시적인 읽기 불일치와
구별되는 결과이며, 물리적인 고장 원인을 단정하지 않는다.

`repair_app_sector.py`는 50kHz에서 해당 페이지를 재확인한 뒤, 검증된 APP 파일의
sector5 전체 128KiB만 0x08020000에 한 번 다시 기록하도록 범위를 제한한다.
순정 BL·설정 영역은 쓰지 않는다. 수정 후 APP 전체 두 번 읽기와 하위 64KiB
불변 확인이 모두 맞아야 성공한다. 모든 원시 데이터와 로그를 보존한다.

sector5 재기록과 검증은 성공했다. 이후 APP 전체를 두 번 독립적으로 읽은 값이
모두 위 SHA-256과 일치했고, 하위 64KiB도 설치 전 그대로였다. 확인 결과는
`sector-repair/results.json`의 `status: pass`다. 재기록 명령은 이 구간에 한 번만
수행했고, 실패 로그나 읽기 데이터를 성공 파일로 덮어쓰지 않았다.

`bringup.py --test-only --cycles 2`로 APP 읽기 일치, 순정 BL을 통한 두 번의
재부팅, HAL/RTOS 진행을 확인했다. `install-verified/summary.json`이 통과했다.
최초 설치 전 디버그 동결 값 0을 복원하고 실제 레지스터를 읽어 확인했다
(`install-verified/restore-original-debug-freeze.log`).
