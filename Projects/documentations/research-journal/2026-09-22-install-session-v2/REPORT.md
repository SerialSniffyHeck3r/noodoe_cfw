# 설치·복구·앱 상태 개선 6.4

소프트웨어 구현 및 오프라인 검증 보고서다. 기기에 기록하지 않았고, 정상 무선 기판·실제 폰으로 설치가 성공했다고 주장하지 않는다. 최종 수치와 SHA는 `verification-summary.json`을 기준으로 한다.

## 변경한 동작

- 최초 설치의 NOR 전체 해시 두 번, 미사용 공간 다운로드, 폰의 128MiB expected.bin을 제거했다. 전체 FAT 소유권 감사, 원본·예정·최종 메타데이터 보관, 쓰기 범위 제한, 물리 읽기 및 SHA 검증은 유지했다.
- Product를 한 번 받은 뒤 A→B 및 최종 staging은 기기 내부에서 복사한다. 내장 순정 APP과 빈 컨테이너도 기기에서 생성한다. 전체 NOR 독립 A/B 백업은 상세 진단 메뉴로 분리했다.
- 순정 복귀 뒤 남은 이전 CFW 때문에 새 설치가 막히는 경로를 수정했다. 기존 CFW A/B/BOOT만 UID·FAT·물리 preimage SHA를 검증하고 재초기화할 수 있다. 이 파일들의 이전 원본은 폰에 먼저 보관하며, FAT·순정 파일·CFWREC·로그·누계는 덮어쓰지 않는다. 일반 사용자의 설정과 CFW 사진 초기화는 정상 CFW 확정 후 기존 정책대로 한 번 수행한다.
- 같은 Gate·자산이면 일상 업데이트는 Product 384KiB만 전송한다. 바뀐 자산만 비활성 자산 슬롯으로 보내고 이전 유효 슬롯을 보존한다. 이전 정상 CFW·60초 건강 확인·BT·앱 재접속·롤백을 유지했다.
- Bootstrap/Product의 공용 InstallSession으로 화면·BT·전원 유지 수명을 관리한다. 파일 사이 idle, IGN OFF, 연결 단절로 메뉴나 절전으로 빠지지 않는다. O를 새로 3초 유지하면 안전 경계에서 취소하며, 이미 확정되었거나 결과 미확인인 설치는 강제로 끊지 않는다.
- 기기/폰 양쪽에서 단계 기준 전체 진행, 현재 파일·섹터·바이트·검증 위치·취소 가능 상태를 표시한다. 렌더링은 최대 5Hz다. 재부팅 중에는 마지막 확인 상태와 연결 대기를 구분한다.
- Gate에 Back to stock / Details / Help, UP/DOWN 탐색, 새 O 2초 복원 확인을 넣었다. 추가 IGN 조작은 요구하지 않는다. Verified는 실제 복구본 검증 뒤 표시한다. Bootstrap과 Gate 글꼴은 ROM 비트맵 기준 110%이며 외장 폰트 의존성이 없다. RadioRecovery는 추가하지 않았다.
- 앱에 기기별 ZIP·표시 상태, 연결 세대 격리, 동일 UID의 이전 불명확 작업 확인을 넣었다. 초기화는 연결·현재 선택만 정리하고 기기 ABORT/RESET을 보내지 않는다. 로그·저널·백업·ZIP·페어링·사용자 설정은 남긴다.
- 시스템/라이트/다크 테마를 설치 화면·다이얼로그·시스템 바에 적용했다. 화면 재생성이 서비스의 소켓을 소유하지 않으며 새 화면은 최신 진행 상태를 받는다. 전송하는 사진·CJK 이미지에는 앱 테마를 적용하지 않는다.
- 중요 변경 전 기록, 실제 TX/RX 바이트, 전체/사용자 대기/실제 작업 시간 기록을 추가했다. 익스포트 후 내부 원본은 남는다.

기존 Product 예산을 통과했다. 힙·스택·통신 큐를 줄이지 않았다. Gate에 BT·RTOS·SDRAM·LVGL·외장 폰트를 넣지 않았다. Cube/벤더 원본·OpenNoodoe 원본은 수정하지 않았다. 실제 Cube GUI 재생성은 이번에 수행하지 않았으며, 기존 생성 계약 검사와 CLI 빌드를 수행했다.

## 검증 범위

- Android JUnit/Robolectric: 기기 분리, 이전 응답 무효화, 중복 초기화, 로그·테마 보존, 양쪽 테마 렌더링, 중복 터치, 전송/복구 회귀. 최종 개수는 JSON에 기록한다.
- 실제 ARM 코드 + 모의 NOR: 9개 파일 생성 결과를 독립 호스트 계획과 전체 바이트 대조; 기존 CFW 재설치; A 및 BOOT 소거 경계의 중단·재개; 기록/메타데이터 공개 중 단절; 범위 밖 쓰기 없음.
- Product updater O0/Os: 수신·검증·취소·체크포인트 재개·저널/자산 조건. Bootstrap/Gate 메뉴·세션·ROM 글꼴·EVE 화면 초기화 시험.
- Resources O0/Os: 514개 전원 차단 경계에서 기존 A 보존, IGN OFF 전송, 기록 전/첫 섹터 이후 취소, 손상·버전·부분 자산 거절.
- 최종 ZIP을 실제 Android production importer와 확보된 BL0.15 실차 식별 증거로 검사했다. 이는 실차 설치 성공의 증명이 아니다.

| 실제 시간 | 결과 |
|---|---|
| Bootstrap 연결 → 최초 CFW 확정 | 미측정: 연결된 정상 무선 기판·폰 없음 |
| 일상 Product 업데이트 → 정상 확정 | 미측정: 동일 사유 |

10분/2분 달성을 실측했다고 보고하지 않는다. 단축 근거는 제거한 전체 검사·중복 전송과 실제 코드의 전송량이며, NOR 소거·프로그램 시간, Bluetooth 응답 왕복, 사용자 확인 대기와 60초 건강 확인은 남는다. 모의 실행 시간은 무선 설치 시간으로 사용할 수 없다.

## 받는 파일과 적용 순서

`NoodoeCompanion-6.4.apk`는 기존 6.3.2와 같은 개발 서명이다. 기존 앱을 삭제하지 말고 덮어설치하면 기록을 유지할 수 있다. ADB `run-as io.noodoe.installer`도 가능하다. 별도로 빌드된 Release APK는 서명이 다르므로 기존 설치 위에 그대로 교체하는 파일로 제공하지 않는다.

새 Gate를 적용하려면 **순정 복귀 → 6.4 ZIP의 새 Bootstrap → Gate+CFW** 순서다. 이미 실행 중인 구 Bootstrap에 새 ZIP을 강제 적용하지 않는다. 이후 같은 Gate를 유지한 버전은 앱의 일상 업데이트를 사용한다.

초기 FAT 파일 공개는 전원 차단에 원자적이지 않다. 손상 FAT는 자동 포맷·수리하지 않고 보관된 메타데이터와 오류를 남긴다. 자산 수신의 RAM 오프셋은 링크 재접속에는 사용할 수 있지만 MCU 리셋 시 다시 받아야 한다. 정상 자산 슬롯은 유지된다.

남은 실증은 정상 폰/무선 기판에서 순정→Bootstrap→CFW→다음 CFW→실패 롤백→버튼 순정 복귀, 각 단계의 실제 IGN/전원 차단, 전송 중 테마 전환, 실제 LCD/FPS/장시간 부하다.
