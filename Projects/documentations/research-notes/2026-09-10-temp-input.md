# AK550 계기판 TEMP+/TEMP− 관측

2026-09-10. 사용자는 차량 계기판 하네스에 TEMP+/TEMP− 단자가 있고, 해당 AK550에는 사용자에게 온도를 보여주는 기능이 없다고 설명했다. 아래 벤치 결과는 사용자 관측이며, 분석 도구가 장치에 접속하거나 신호를 주입한 결과는 아니다.

> 사용자 추가 정정: **센서 실물은 없고 TEMP+/TEMP− 핀만 있다.** 순정 센서를 측정하는 절차가 아니라 [개방 전압·파형·제한 저항 부하로 입력을 특성화하는 절차](2026-09-10-temp-pin-measurement-plan.md)를 작성했다. 이후 일부 전기 관측이 보고돼 아래에 기록했다.

## 현재 작업 결정: 온도 입력 추적 보류

사용자는 103 가변저항을 돌려 TEMP 단자의 전압을 변화시켜도 **관측한 UART 프레임에는 전혀 변화가 없었다**고 추가 보고했다. 이는 사용자 관측이며, 이번 갱신에서 새 UART 원본 파일을 독립적으로 분석한 결과는 아니다. 실제 전압 범위·유지 시간·기동 조건을 추가로 가정하지 않는다.

따라서 현재 AK550 Noodoe 커스텀 펌웨어 연구에서는 TEMP 입력과 payload 8의 활용을 **보류하고 우선순위를 낮춘다.** 이 결정을 위해 추가 시험을 요구하지 않는다. 프로토콜 분석에서는 payload 8의 바이트 위치와 기존 raw−40 처리 근거를 보존하되, 실측 온도로 표시하거나 기능에 연결하지 않는다. 프레임에서 해당 바이트를 제거하거나 길이·체크섬 계산에서 제외하는 뜻은 아니다.

기록할 결론은 **시험한 TEMP 전압 변화에 관측 UART 무반응 / TEMP와 payload 8의 연동 미확인**이다. TEMP 핀이 모든 조건에서 미사용이거나, payload 8이 모든 모델·버전에서 의미 없다는 결론으로 확대하지 않는다.

## 사용자 추가 실측: 5V/0V와 103 가변저항

- 두 TEMP 핀은 한쪽 약 5V, 다른 쪽 약 0V라고 보고했다.
- `103` 가변저항의 **가운데 다리(와이퍼)에 −, 바깥 다리 하나에 +**를 연결했다. 스코프 팁은 **+에 연결한 바깥 다리**, 즉 계기판 단자 자체에 연결했다고 확인했다.
- 가변저항을 돌리면 그 측정 노드 전압이 내려간다고 보고했다. 이후 UART 프레임은 변하지 않았다고 확인했다. 실제 저항값별 전압 수치·변동 범위는 확보하지 않았으며, 이 후속 관측의 새 파형/시리얼 파일을 이번에 분석하지 않았다.

이 배선은 두 단자 사이의 저항을 변화시키는 방식이다. 바깥 두 다리에 고정 전압을 주고 와이퍼 전압만 읽는 일반 분압기 실험과 구분된다. 따라서 **계기판 TEMP 단자의 전압이 외부 저항 부하에 따라 변한다**는 의미 있는 관측이다. 5V 계열 바이어스와 내부 저항을 통해 저항식 센서를 읽는 구조가 강한 후보가 됐다. 다만 실제 ADC 소비, NTC/PTC 종류·규격과 UART payload 8 연결까지 확인한 결과는 아니다. 내부 회로가 수동 풀업 하나인지, 능동 바이어스·전류 제한 등이 있는지도 미확인이다.

아래는 향후 이 조사를 재개할 때 참고할 방법이며 현재 추가 시험 요청은 아니다. 높은 저항 설정에서부터 외부 저항값·단자 전압·정상 UART 전체 프레임을 묶는다. 가변저항 저항값은 전원을 끄고 회로에서 한쪽을 분리한 상태에서 측정해야 하며, 전원 ON 상태의 저항 모드나 0Ω 끝단 시험은 피한다. 안정된 DC일 때만 기존 측정 절차의 등가 저항식을 적용한다.

가변저항 결선의 일반 근거: [Bourns Trimmers FAQ](https://www.bourns.com/de/resources/faqs/faq-trimmers)는 와이퍼와 바깥 단자 하나를 쓰는 가변저항 모드와 분압기 모드를 구분한다. 이는 가변저항의 사용 방식에 대한 근거이며 AK550 내부 회로의 증명은 아니다.

## 현재 구분

- 온도 입력 회로의 존재와 운전자에게 온도를 표시하는 기능의 존재는 별개다. 공용 설계, 미사용 옵션, 다른 모듈로 전달하는 입력 등은 가능한 설명이지만 AK550에서 채택한 이유로 확정하지 않는다.
- AK550 정비매뉴얼 §9-53의 공식 PDF 검색 색인에는 계기판 주변 `Room temp sensor`, `TEMP`, `GND(TEMP)`가 나온다. 따라서 **외기온 센서 입력이 현재 우선 후보**다. 냉각수 WTS의 저항 규격을 이 단자에 그대로 적용하지 않는다.
- 사용자가 확보한 하네스 TEMP+/TEMP−와 해당 도해 신호의 물리 대응은 원문 배선도·차량 배선으로 확인해야 한다. 명칭만으로 커넥터 캐비티 번호를 새로 만들지 않는다.
- 2017년 KYMCOLUX AK550 사용자매뉴얼의 표시 기능 설명(웹 페이지 16–19)에서 외기온 숫자 표시를 확인하지 못했다. 모든 지역 사양에 대한 부재 증명은 아니다.

## 저항식 후보와 시험 준비

`+ / −` 표기만으로 NTC 써미스터라고 확정할 수 없다. 저항식이라면 측정 입력과 센서 리턴을 구분한 이름일 수 있으며, 일반적인 2단자 써미스터 자체는 극성이 없다. TEMP+를 외부 12V 주입 단자로 취급하지 않는다.

순정 센서의 실체와 저항-온도 규격을 확인한 뒤 부품을 고른다. NTC라 해도 기준 온도의 저항값과 온도 특성이 서로 다를 수 있어 아무 10kΩ 써미스터나 연결해 정확한 온도를 기대할 수 없다. 기능 유무 확인만이라면 적절한 범위의 고정 저항으로도 입력을 모사할 수 있지만, 그 전에 TEMP 양단 개방 전압과 센더 대응을 확인해야 한다. 정격을 모르는 상태에서 단락 또는 임의의 작은 저항을 연결하는 절차를 제시하지 않는다.

## Noodoe 펌웨어와의 연결 한계

V5.16의 UART CMD21/22 parser는 payload 8에서 40을 뺀 값을 구조체 +4의 16비트 값으로 저장한다. 현재 GAS1/fuel0를 포함한 정상 캡처에서 이 바이트는 00이며, 이를 실제 −40°C로 해석하지 않는다.

TEMP 전압을 바꾼 시험에서 UART가 변하지 않았다는 사용자 관측에 따라 이 필드와 TEMP 단자의 연결은 입증되지 않았다. 온도 단위·센서 정체와 1°C당 1 증가하는 인코딩인지도 미확인이며, 현재 조사는 보류한다.

기존 두 UI getter 소비 함수 `0x0801BD82`, `0x0801CC88`는 해당 구조체 +4를 읽는 것으로 확인되지 않았다. 따라서 온도 수신/저장이 있다는 사실을 숫자 온도 위젯이나 경고 기능의 구현으로 확대하지 않는다. 이것은 V5.16 OTA의 한정 분석이며 실물 전체 버전과의 동일성은 검증하지 않았다.

APK의 `TemperatureWidget`은 weather 계열이며 `WeatherAdapterImpl`이 `FullWeatherData`에서 기상 온도를 만들어 보내는 별도 경로다. 이름만 보고 차량 TEMP 입력과 연결하지 않는다. `OQCDataExt`의 `ThresholdWaterTemp` 역시 공장 검사 관련 명칭이며 해당 하네스나 payload 8의 원천을 입증하지 않는다.
