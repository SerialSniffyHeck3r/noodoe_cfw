# 설치 상태·오류·정체 대응 강화

2026-09-21. Android NoodoeInstaller와 Bootstrap을 수정했다. OpenNoodoe 원본과 순정 BL은 수정하지 않았다. 이 폴더의 APK/ZIP은 새 후보이며 이번 작업에서는 장치 접근·설치를 하지 않았다.

## 사용자가 보는 동작

폰의 진행 패널과 foreground 알림은 작업 스레드와 별개로 매초 갱신된다. 현재 단계, 처리 바이트/단계별 %, 전체 경과 시간, 단계 경과 시간, 마지막 검증된 응답 시각, 현재 단계의 평균 전송률과 예상 잔여 시간이 나온다. 한 파일이100%가 되어도 전체 설치가 끝났다는 뜻으로 표시하지 않는다. 파일 생성, 보존 해시 검사, 이미지 전송, 기기 버튼 확인, 재시작,60초 정상 실행 및 영구 확정을 분리한다.

오류가 나면 설명·상세 코드·다음 행동을 표시하고, 순정/Bootstrap/Product에 따라 복구 안내를 다르게 제공한다. Bootstrap에서는 Back to stock → O를 놓았다가 새로2초 유지, Product 독립 Gate 진입에는 기존 IGN+O 동작을 안내한다. 앱을 다시 열면 마지막 표시를 참고용으로 복원하며 명령을 자동 재개하지 않는다. 확정 권한은 기존 체크섬/동기 기록 저널에서만 판단한다.

누도는 현재 파일의 이름과 단계, 진행이 마지막으로 바뀐 뒤 지난 시간을 표시한다. 화면 문구와 진행바가 겹치던 위치를 조정했다. SYSTEM ERROR는 붉은색, 그 아래에는 `aw shit :(`, 상세 코드는 별도로 표시한다. 최초 오류는 다음 상태 조회 성공이나 후속 오류로 사라지지 않고 O를 누를 때까지 보존한다.

## 멈춤의 처리 범위

| 관측 | 처리 |
|---|---|
| 폰 SPP connect/write15초 초과 | 소켓을 닫아 블로킹 해제. 결과 미확인으로 처리하며 쓰기 자동 재전송 없음 |
| 검증된 응답15초 이상 없음 | 폰에 응답 대기/결과 미확인 경고. 사용자 확인·재부팅·정상 실행 확인 같은 의도된 대기는 별도 표시 |
| 응답은 있지만 작업량30초 이상 그대로 | 폰과 누도에 진행 정체 경고. heartbeat만 증가한 것을 진행으로 세지 않음 |
| Bootstrap 저장 작업120초 이상 진행 없음 | 완료된 NOR 호출 사이에서 FAILED/BS_TIMEOUT, 쓰기 권한·백업/영역 검증 증명 폐기. 이후 추가 쓰기 방지 |
| 화면 FIFO/swap 미완료 또는 버스 실패10초 지속 | DISPLAY 원인 코드를 폰에서도 조회 가능. 쓰기 도중 EVE 강제 재초기화하지 않음 |
| MCU 자체 실행 정지 | 기존 IWDG 및 초기 복구 경로 유지. 이번 변경으로 모든 CPU/전원 장애가 실증된 것은 아님 |
| 새 CFW 재연결/정상 실행 확인 | 재접속마다 확인 제한 시간을 새로 시작하지 않고 하나의175초 창 공유. 개별 IO가 제한시간 경계를 넘길 수는 있음 |
| COMMIT/RESET 또는 복구 응답 손실 | 성공/취소로 판정하지 않음. 상태/실제 부팅을 확인하며 파괴적 명령 반복 없음 |

120초 처리는 물리 쓰기의 도중에 인터럽트로 끊는 방식이 아니다. 최초 FAT 할당 중간 상태를 자동 복구 가능한 원자적 저장으로 바꾸지도 않는다. 파일 생성 중단은 기존 복구 자료와 오류를 보존하고 자동으로 반복하지 않는다.

## 내부 변경

- Android: `InstallerPresentation`(스레드 안전 표시 모델), `InstallerFailure`(역할별 안내), `TransportDeadline`(소켓 제한시간), `BootstrapProgress`(읽기 전용 세부 상태), `LoggedInstallerProgress`(내용을 제외한 단계/오류 로그).
- 유지보수 서비스가 단일 소켓/송신을 계속 소유한다. 별도의 상태 폴링 소켓을 만들지 않는다. 느린 IO와 독립된1초 UI ticker를 사용한다.
- 기존 NDCP0x5A/36B는 유지하고,0x84/schema2/64B 상세 상태를 추가했다. phase/subphase/file/position/total/error/heartbeat/idle/connection epoch를 포함한다. 명세는 `NoodoeInstaller/PROTOCOL.md`.
- 오류 상위16비트는 BT/NOR/RAM/DISPLAY/STORAGE/UPDATE 출처, 하위16비트는 상세 코드다. 예: `00050004`=저장 작업 IO, `0005000A`=저장 작업 정체. 종전의 충돌 가능한 단일 숫자 해석을 없앴다.
- 폰 세션 로그에 phase·진행량·기기 오류·연결 세대를 기록한다. 알림/사진/곡명 등 자유 텍스트를 넣지 않는다. 저장은 단계 변경 시 또는5초 간격이며 로그 쓰기 실패 시 다음 작업을 계속하지 않는다.
- UI와 오류 화면은 고정 버퍼/ROM 글꼴을 유지한다. 새로운 폰트 자산이나 기기 힙을 요구하지 않는다. Cube 생성 파일/vendor 소스는 바꾸지 않았다.

## 검증과 한계

정확한 빌드 크기·해시·시험 결과는 `verification-summary.json`과 `test-results/`에 고정한다. Android JVM 시험, 실제 ARM C의 O0/Os UI 및 SPI/FIFO 오류 주입,9개 파일 저장의 각 쓰기 상태 timeout 주입, 기존 파일·예약영역 보존 및 재접속/변조 검출을 확인한다. Product Release/Debug 메모리 예산도 재검사했다.

정상 무선 기판의 BT 통신, 실제 Android 화면/알림 렌더링, 물리 전원 차단 및 실차 BL0.15 중단 복구는 이번 작업의 검증 범위 밖이다. 표시 보강만으로 최초 FAT 생성이나 순정 BL 설치의 전원 중단 위험이 제거됐다고 주장하지 않는다. 기기 로그 저장소가 준비되기 전의 새 상세 상태는 RAM/연결된 폰의 로그에서 제공하며, 전원이 끊기기 직전의 모든 상태를 기기 NOR에 보존한다고 주장하지 않는다.

새 파일은 `NoodoeInstaller-status.apk`, `vehicle015/installer.zip`. 새0x84 상태를 지원하는 Bootstrap이 포함된 ZIP과 앱을 함께 사용한다. 실기기에 이번 버전을 설치한 상태는 아니다.
