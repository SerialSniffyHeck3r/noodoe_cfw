# 순정 복귀 / 삭제 전용 펌웨어 구현 결과

2026-09-23. 연결된 벤치·ST-LINK·UART·ADB·GUI에 접근하지 않았다.
코드, 빌드, ARM 모델, Android JVM/Robolectric 검증과 배포를 수행했다.

## 구현

앱의 순정 복귀 선택은 KEEP_CFW_DATA가 기본이다. 이 경로는 기존 Gate를 사용하며
Gate·Bootstrap 바이너리는 직전 배포와 바이트가 같다. 긴급 버튼 복구에 삭제를
추가하지 않았다. 새 ERASE_CFW_DATA 경로는 Product의 공용 NDCP 업데이트 서비스로
검증된 독립 UninstallBootstrap을 올리고 순정 BL을 통해 실행한다.

Product가 광고하는 UID·기능·정확한 uninstall SHA와 앱 패키지를 대조한다. 임의
APP 주소/바이너리를 새 설치 경로에 전달할 수 없다. 전송 끝의 물리 CRC/SHA와
기존 설치 메타데이터 검증을 유지했다. 불명확 COMMIT/RESET은 상태부터 조회하며
동일 이미지를 중복 기록하지 않는다. 로그 회수는 가능한 범위에서 먼저 하고 폰의
증거·로그는 유지한다.

삭제 실행부는 공용 NOR·EVE ROM·버튼·워치독·압축 순정 소스·복구/메타데이터 코드를
사용한다. BT/RTOS/LVGL/SDRAM은 링크하지 않는다. 첫 APP 섹터 중 4KiB는 진입부,
60KiB는 내부 작업 기록, 뒤 384KiB는 코드와 순정 이미지다. 링커와 이미지 검사로
경계를 강제한다. Cube 생성 파일을 수정하지 않고 독립 빌드 경로를 추가했다.

기기에서는 KEEP를 기본 선택으로 표시한다. 완전 삭제하려면 UP/DOWN으로 ERASE를
고른 뒤 O를 놓았다가 2초 눌러야 한다. 승인 전 FAT 전체 소유권·각 컨테이너의
UID/형식·내장 순정 이미지를 검사하고, FAT/디렉터리 원본 36KiB와 계획을 내부
저널에 읽기 검증·commit-last로 남긴다. 승인 후에는 IGN/폰과 무관하게 실행한다.

소유권이 확인된 CFW 클러스터의 전체 내용과 슬랙을 4KiB씩 실제 NOR에서 소거·조회한다.
FAT 두 사본의 해당 연결만 해제하고 디렉터리를 삭제 표시한다. 다른 파일과 공유하는
소거 단위, 교차 연결, 모르는 소유권, 손상 FAT는 거부한다. 변경 중 재시작하면 내부
저널 원본·의도 기록으로 이어간다. 자동 포맷은 없다. 삭제된 파일의 옛 디렉터리
메타데이터 31바이트는 표준 FAT 삭제 방식대로 남으며 전체 매체 포렌식 소거는 아니다.

대상은 9개 기본 컨테이너와 명시적으로 소유권이 증명되는 CFWTEXT.DAT다. 현재
과거 WALL*.JPG 생성 이력을 증명할 수 없으므로 삭제하지 않는다. 이름만 같은 캐시나
미지원 형식은 거부한다. 이 제한과 CFWTEXT identity 형식은 UninstallBootstrap/README.md에
기록했다. 순정 파일·사진·BL 실행 코드·공장 영역은 삭제 대상이 아니다.

완료 후 내장 순정 V5.16 APP을 기존 staging에 기록·검증하고 순정 BL로 설치한다.
그 설치가 정상 완료되면 삭제 실행부와 내부 저널도 순정 APP으로 교체된다. 삭제 후
CFWREC.DAT가 없어도 복구 이미지의 출처는 내부 플래시다.

폰은 BT 없는 단계에서 진행률을 추측하지 않는다. 순정 복귀 확인으로 버전·모델/PCBA·
Bluetooth 주소를 대조하고, 연결 실패는 미확인으로 남긴다. 기기에서 최종적으로
KEEP/ERASE 중 무엇을 선택했는지는 stock SPP로 관측할 수 없어 로그에 별도 한계를
기록한다. 순정 검출 성공을 데이터 삭제 성공 증거로 쓰지 않는다.

데이터 유지 후 설치 계속에서 복원/새로 시작을 고른다. 복원은 기존 설정·주행·사진
컨테이너가 검증되어야 하고 trial에서는 읽되 설정을 쓰지 않는다. 최초 generation 1의
명시적 복원 마커를 정상 확정 때 소비하여 해당 설치의 초기화만 생략한다. 이후
일반 업데이트는 기존 초기화 정책 그대로다.

새 Product 메타데이터 writer 때문에 처음에는 64KiB 여유 기준을 넘지 못했다.
GPS 위도 전용 cosine을 ±90° 한정 float 다항식으로 바꿔 범용 libm의 큰 각도 감소
코드를 제거했다. 1,800,001개 float32 비교에서 최대 오차 2.613e-7, 기존 Q10 투영
계수 차이는 최대 1이다. 대시보드 실제 ARM 모델도 검사했다. UI 기능·힙·스택·통신
용량이나 예산 기준을 줄이지 않았다.

## 검사 결과와 범위

- ARM 삭제 코어: 기본 쓰기 그래프 247개 동작 각각의 직전/중간 중단 및 5개 거부
  조건, 총 499개 통과. 최신 코어 재검사 51개, 추가 소유권/보고된 I/O 오류 7개 통과.
- 4,390,912 B 파일과 슬랙을 비FF 데이터로 채운 별도 시험: 실제 모델 소거·FAT 반환,
  1,309개 변경 동작과 파일별 마지막 소거의 torn-reset 9개 재개 검사 통과.
- Product 공용 수신/업데이트 회귀, 최종 uninstall pin의 448KiB 전송·검증·확정,
  잘못된 pin 거부, 복원 마커 소비/다음 업데이트 초기화: O0/Os 모델 통과.
- 기존 설정/사진/저널 검사, trial 부팅 8개, 공용 복구 엔진 및 메타데이터 writer 중단
  모델 검사 통과. 초반 harness의 비동기 FINISH 처리와 사진 reset stub 누락은 수정 후
  재실행했다. 초기 실패 로그도 보존했다.
- Android 194개 시험, 오류/실패 0. Lint 오류 0, 기존 경고 81. APK 6.7.0/code11,
  기존 서명 유지, 실제 배포 ZIP을 생산용 Android importer로 검증했다.
- Product Release/Debug 예산 검사 및 Cube 생성 연결 계약 검사 통과. 새 startup/linker는
  프로젝트 소유이며 GUI에서 재생성을 직접 실행했다고 주장하지 않는다.

실제 RF 전송, 정상 무선 기판의 두 복귀 경로, 실제 전원 중단, 원래 BL의 중단 후 설치
재개, 실차 보관 데이터 복원은 미검증이다. 실제 설치 시간은 아직 없다. 모델의 소요
시간을 실기기 설치 시간으로 표시하지 않는다. 특히 순정 BL로 넘기는 내부 메타데이터
변경/원래 BL 설치 구간의 전원 중단은 이번 코어 모델만으로 복구를 보장할 수 없다.
