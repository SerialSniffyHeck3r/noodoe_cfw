# Noodoe 전원 상태 입력과 슬립·종료 경로

> **2026-09-11 실물 갱신:** 사용자가 12V 두 접점 중 하나를 IGN으로 식별해 ON/OFF 문제를 해결했다. 하단의 ‘IGN에 따른 접점 변화 없음’은 그 이전의 측정 보고이며 최신 기능 판정으로 사용하지 않는다. IGN 접점과 MCU PG13 사이 회로는 아직 미추적이다. [IGN 및 6핀 CN3 리셋 후보 관측](2026-09-11-ign-cn3-reset-candidate.md).

2026-09-10 KST. 기준은 보존된 SR1.5 V5.16 BIN이다. 실제 보드에 접속하거나 신호를 주입하지 않고 원시 명령어와 초기화 테이블을 분석했다.

**전원 ON/OFF 상태를 읽는 MCU 신호는 PG13으로 식별했다. MCU 입력 기준 HIGH는 OFF, LOW는 ON이다.** 다만 이를 바로 ‘CN 몇 번 슬립 핀’이라고 부를 수는 없다. MCU GPIO와 커넥터 사이 회로는 아직 추적하지 않았고, 확인된 종료 경로에는 외부 전원 제어용으로 보이는 출력 및 리셋이 있다. 별도로 존재하는 MCU STOP 함수와 이 OFF 경로의 연결은 확인되지 않았다.

### 같은 날 후속 관측: 누도 분리 상태의 IGN 비교

사용자는 **Noodoe를 뽑고 계기판 쪽의 모든 CN 접점**을 IGN ON/OFF로 비교했으나 전압 변화가 없었으며, 12V 두 접점도 IGN OFF에서 공급이 유지됐다고 확인했다. 원래 계기판과 Noodoe를 직접 연결했을 때는 계기판을 끄면 Noodoe도 꺼졌다. 현재의 Noodoe 독립 전원 구성과 위 분리 측정은 다른 조건이다. IGN 전환 때 UART 프레임이 계속되는지·바뀌는지·멈추는지는 미확인이다. 화면 꺼짐만으로 MCU STOP이나 내부 전원 차단까지 판정하지 않는다.

이 결과를 ‘연결 상태에서도 IGN 정보를 전달하는 선이 없다’로 확대하지 않는다. **Noodoe 쪽에 외부 풀업이 있고 계기판이 선을 GND로 당기거나 개방하는 회로**라면, 분리된 계기판 접점만의 전압 측정으로 두 상태를 구분하지 못할 수 있다. 이는 가능한 회로 예시이며 실제 회로를 식별한 결과가 아니다. 앞서 CN1의 3.3V가 Noodoe 연결 때만 나타났다는 관측은 연결 조건에 따라 바이어스가 달라질 수 있다는 근거이지, 그 네 선이 IGN 또는 PG13이라는 증거가 아니다. [TI: 오픈드레인 출력과 풀업](https://www.ti.com/lit/an/slva485/slva485.pdf).

PG13은 공장 검사 전용 판독이 아니다. TIM2 콜백 `0x08043C38 → 0x08043CE0`은 일반 동작에서도 입력을 처리하며, OQC 객체가 없을 때 OFF 이벤트는 일반 종료 처리로 이어진다. 다만 **PG13을 차량 IGN 선과 동일시한 설명은 미확인 연결을 앞서간 해석**이다.

UART 타임아웃도 다시 원시 코드로 대조했다. 확인한 `0x0804E84E → 0x08033242 → 0x08031144 → 0x08033084 → 0x0804E730`은 400/800 tick의 감시 이후 링크 재초기화와 CMD01=04 재요청으로 이어진다. 이 경로를 통신 중단에 의한 슬립이라고 부르지 않는다. F5 수신기는 21/22/41/42를 허용하며, 기존 CMD01=00 종료 프레임은 **Noodoe→계기판 송신**이다. 이를 반대 방향의 Noodoe 종료 명령으로 제안하지 않는다. 다른 종료 정책의 전수 배제는 아니다.

다음 관측은 독립 전원을 섞지 않은 **원래 계기판–Noodoe 연결 상태**에서 수행한다. 연결을 유지한 채 CN 접점의 ON/OFF 전압·전환 순간 파형을 읽고, UART를 ON부터 OFF 후까지 연속 기록한다. 12V 두 선도 부하가 연결된 이 조건에서 함께 확인한다. 분리 상태와 연결 상태의 측정값은 별도 표로 남긴다.

## 1. 이번에 답할 수 있는 범위

| 질문 | 결론 |
|---|---|
| 펌웨어가 ON/OFF 상태로 해석하는 GPIO 입력이 있는가? | 그렇다. GPIOG pin 13, 즉 PG13. 차량 IGN과의 물리 연결은 미확정 |
| 극성은? | MCU PG13 LOW → 내부 ON, HIGH → 내부 OFF |
| UART 데이터 중 하나를 읽은 결과인가? | 이 경로는 GPIO 직접 판독이다. UART F5 페이로드에서 얻는 상태가 아님 |
| 커넥터의 어느 접점인가? | 미확정. PG13에서 앞단 회로와 CN까지 물리 추적 필요 |
| CN에서도 HIGH=OFF인가? | 미확정. 앞단의 반전·분압·버퍼·트랜지스터 유무를 모르므로 MCU 극성과 구분 |
| MCU STOP 구현이 있는가? | 있다. `0x0804260C → 0x0804DB80 → WFI` |
| PG13 OFF가 그 STOP을 호출하는가? | 현재 확인하지 못함. 함수 존재와 정상 종료 시 호출을 구분 |
| 확인된 다른 종료 동작은? | PD13·PG14·조건부 PI9 출력 변경, 별도 경로의 시스템 리셋 |

실물 도너는 2017 AK550 계기판과 별도 Noodoe 세트다. V5.16과 실제 도너의 설치 버전 동일성, MCU 전체 마킹·패키지 및 공식 CN 접점 번호는 여전히 별도 확인 사항이다. PG13은 포트명이며 MCU 패키지의 ‘13번 다리’라는 뜻이 아니다.

## 2. PG13 식별의 원시 근거

IAR 시작 코드로부터 앞서 복원한 `.data` 초기값에서 두 테이블을 대조했다. 이 파일은 실제 RAM 덤프가 아니라 동일 BIN의 초기값을 복원한 자료다.

| 테이블 | 사용한 슬롯 | 값 |
|---|---|---|
| GPIO 포트 표 `0x20000998` | `+0x18`, index 6 | `0x40021800` = GPIOG |
| GPIO 마스크 표 `0x20000A20` | `+0x1A`, index 13 | `0x2000` = pin 13 |

`0x08043CE0`의 상태 처리 루틴이 이 포트와 마스크를 사용해 `0x080355F2`의 GPIO 입력 판독 함수를 호출한다. 현재 입력과 `0x20023302`의 이전 ON 상태를 비교한다.

GPIO 초기화 `0x08036C8A` 부근에서도 port=`0x40021800`, pin mask=`0x2000`, mode=`0x10310000`, pull=`0`이 확인된다. 이는 **PG13 입력, 내부 풀업·풀다운 없음, EXTI13 상승·하강 양에지** 설정이다. EXTI15_10 IRQ40의 vector `0x080100E0`는 `0x08070DE9`를 가리킨다.

```text
PG13 HIGH, 이전 ON=1
 → 0x08043D54: ON 캐시를 0으로 변경
 → 0x08031DC8: 등록 callback에 0 전달
 → 0x08032608: 0x08076B48[0] = 0x00000008
 → event category 0 / subtype 1 = OFF

PG13 LOW, 이전 ON=0
 → 0x08043D8A: ON 캐시를 1로 변경
 → 0x08031DB4: 등록 callback에 1 전달
 → 0x08032608: 0x08076B48[1] = 0x00000010
 → event category 0 / subtype 2 = ON
```

같은 상태를 계속 읽을 때 매번 ON/OFF 이벤트를 내는 구조가 아니라 상태 변화와 캐시를 비교하는 경로다. 에지 시각 기록 후 시간 차가 `0x0B` 미만이면 판독을 미루는 조건도 있다. TIM2의 1MHz 카운터·ARR999와 update마다 증가하는 tick에 대응하므로 **정상 클록 기준 약 11ms 이후의 판독**이다. 실제 에지부터 이벤트까지 정확히 11ms라고 실측한 것은 아니다.

부팅 초기화 `0x08037298`도 PG13을 읽어 HIGH→0, LOW→1로 저장한다. 이때의 부팅 상태 변수 `0x2002330E`와 실행 중 ON 캐시 `0x20023302`는 구분한다.

앱 이벤트 처리기 `0x080301C8`의 subtype 1은 공장 검사 상태의 ON 비트를 지우고, subtype 2는 설정한다. 휴대전화에 보내는 OQC C4 생성기 `0x08029C8A`도 ON일 때 bit0, OFF일 때 bit1을 만든다. 따라서 과거 문서의 ‘Power OFF pressed’라는 표현을 **별도의 OFF 버튼이 있다는 증거**로 쓰지 않는다. 이 두 비트는 같은 ON 상태의 정·반대 표현이다.

## 3. OFF 이벤트가 들어온 뒤의 처리

OFF 입력을 감지하는 것과 모듈이 최종적으로 꺼지는 것은 여러 단계를 거친다.

`0x080301C8`의 subtype 1 경로에는 다음 처리가 있다.

1. OQC 검사 중에는 검사 상태를 갱신하고 일반 종료 처리를 우회하는 분기가 있다.
2. 일반 경로는 UI 콜백에 이벤트를 전달하고 설정 보존 작업을 수행한다.
3. `0x20023303`, `0x08025198()`의 상태 등 조건을 확인한다.
4. 설정 key `0x13`이 `0xA5A50000`인 분기에서 `0x08032872(1, 60000)`을 호출한다.

`0x08032872`는 백라이트 목표 0 설정, 표시·센서 관련 정리 함수를 호출하고 타이머를 설정한 뒤 key `0x13`을 `0xA5A50002`로 바꾼다. `60000`은 타이머 API에 전달되는 값이다. 약 60초의 지연을 예상하는 근거가 되지만 **모든 OFF 입력이 정확히 60초 뒤 STOP에 들어간다는 뜻은 아니다.**

타이머 descriptor `0x08076D5C`는 callback `0x08032A1E`를 가리킨다. 이 콜백은 설정·작업 상태에 따라 이벤트를 생성하거나 종료 처리를 진행한다. 예를 들어 key `0x13=0xA5A50002`이며 내부 플래그가 0인 분기는 subtype 15를 만들어 `0x08032990`으로 이어진다. 그 안에도 검사 조건이 있고, 통과하면 key `0x13=0xA5A50003`, 정리 함수, 아래의 리셋 경로로 이어진다. 다른 종료 경로에는 `10000` 타이머를 설정하는 재시도 조건도 있다.

현재 값만으로 의미를 확정하지 못한 플래그에는 ‘업데이트 중’, ‘사진 전송 중’ 같은 이름을 임의로 붙이지 않았다. 실물에서 화면이 먼저 꺼지고 나중에 소비전류나 UART가 달라지는지를 시간축으로 관측하면 이 단계를 구분할 수 있다.

## 4. MCU STOP과 전원 제어 출력을 구분

### 4.1 실제 STOP 함수

```text
보드 함수표 0x20000970 + 0x0C
 → 0x0804260C
 → 전력 관련 준비 함수 0x08046588
 → 0x0804DB80(r0=1, r1=1)
 → PWR_CR: PDDS=0, LPDS=1
 → SCB_SCR: SLEEPDEEP=1
 → 0x0804DBA0: WFI
 → 복귀 후 SLEEPDEEP 해제
```

레지스터와 인수의 의미는 ST의 `HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI)`와 합치한다. 이는 내부 SRAM을 유지하는 STOP 계열이며 Standby 진입과 다르다. [ST 공식 PWR 구현](https://github.com/STMicroelectronics/stm32f4xx-hal-driver/blob/master/Src/stm32f4xx_hal_pwr.c), [인수 정의](https://github.com/STMicroelectronics/stm32f4xx-hal-driver/blob/master/Inc/stm32f4xx_hal_pwr.h).

그러나 보드 함수표의 **`+0x0C`를 정상 OFF 경로에서 호출하는 지점을 아직 찾지 못했다.** 직접 분기·리터럴·복원 초기화 표를 조사한 결과이며 가능한 모든 간접 호출의 부재를 증명한 것은 아니다. 따라서 ‘PG13을 HIGH로 만들면 이 STOP에 들어간다’고 결론내리지 않는다.

### 4.2 실제 종료 경로에서 호출되는 출력 제어

`0x08031C26`은 보드 함수표 **`+0x10`**을 호출한다. 위 STOP 슬롯과 다르며 대상은 `0x0804261E`다.

이 함수에서 원시 코드로 확인한 순서는 다음과 같다.

| 순서 | 동작 |
|---|---|
| 1 | PG13 재판독. LOW이면 반환값 `0x0C`로 종료 |
| 2 | PG13 HIGH이면 인터럽트 차단 |
| 3 | **PD13 LOW** 출력 |
| 4 | **PG14 HIGH** 출력 |
| 5 | 보드 revision 값 `0x2002330D >= 3`이면 **PI9 HIGH** 출력 |
| 6 | 카운터를 0에서 16,000까지 증가시키는 루프 후 반환 |

이 순서에는 WFI가 없다. 핀 조합과 종료 시점으로 볼 때 **전원 유지·차단 회로를 제어하는 후보**지만, PD13을 `POWER_HOLD`, PG14를 `POWER_CUT`이라고 공식 명명할 회로도 근거는 아직 없다. 외부 레귤레이터, 래치, 다른 보드의 입력 중 어디로 이어지는지 추적해야 한다. 루프 횟수는 고정된 밀리초 지연으로 환산하지 않는다.

### 4.3 별도의 출력 변경과 리셋 경로

`0x08031C68`은 조건을 검사하고 보드 함수표 **`+0x20` → `0x080427FA` → `0x08043C50`**을 호출한다.

여기서는 PD13을 LOW로 만들고, revision≥3에서 PI9 HIGH → PG14 LOW → PI9 LOW와 사이 지연을 수행한다. 끝의 `0x080366FE → 0x080366A6`은 SCB AIRCR에 key와 **SYSRESETREQ**를 기록한다. 즉 이 경로는 **MCU 시스템 리셋 요청**까지 확인된다.

리셋 뒤 하위 부트 코드가 어떤 전원 상태를 선택하는지는 이 OTA만으로 전체를 확인할 수 없다. 이 점에서도 미보존 하위 플래시가 중요하다.

### 4.4 일반 유휴 WFI도 별도로 존재

`0x08035046`의 WFI는 RTOS tickless idle 경로에 있다. 작업이 없는 동안 잠깐 CPU를 대기시키는 구현이므로 전원 OFF 핀과 바로 대응시키지 않는다. USB 수신 관련 플래그가 이 유휴 WFI를 억제하는 경로도 확인했다. USB 연결 상태를 실험 조건에 남겨야 하는 이유다.

## 5. 세 CN에서 무엇을 찾을 것인가

지금 찾을 대상은 하나의 막연한 ‘슬립 핀’보다 구체적이다.

| MCU 신호 | 펌웨어에서 확인한 역할 | 실물에서 확인할 연결 |
|---|---|---|
| **PG13** | ON/OFF 상태 입력. LOW=ON, HIGH=OFF | CN 또는 전원 감지 회로에서 이 입력까지 이어지는 경로 |
| PD13 | 종료·리셋 경로에서 LOW 출력 | 전원 유지·제어 회로 후보 |
| PG14 | 종료 경로 HIGH, 리셋 경로의 특정 revision에서 LOW | 전원·리셋 관련 제어 회로 후보 |
| PI9 | revision≥3의 종료·리셋 시 출력 변화 | 해당 실물 revision에 적용되는 추가 제어 회로 후보 |

모든 신호가 외부 CN으로 나간다는 보장은 없다. PG13이 보드 내부에서 12V 입력을 감지하는 회로에 이어질 수도 있고, 나머지 출력은 내부 전원 IC에만 연결될 수도 있다. 따라서 ‘세 CN 중 하나는 반드시 전용 슬립 입력이다’는 가설은 아직 확정할 수 없다.

기존 CN 관측을 적용하면:

- **CN1의 3.3V 네 선:** 풀업 신호 가능성이 남아 있다. PG13이 직접 연결돼 있다고 가정하지 않는다.
- **CN2의 0V 열네 선:** ON 상태의 PG13 자체도 LOW이므로, 0V라는 이유로 신호 후보를 제외할 수 없다. 이는 CN2에 PG13이 있다는 뜻은 아니다.
- **CN3의 12V 두 선:** 상시 전원과 키 연동 전원일 가능성도 조사할 수 있으나 현재는 두 선에서 12V를 봤다는 근거뿐이다.
- **CN3의 버튼 관련 5V 세 선:** 버튼에 따른 LOW는 별도로 확인된 기능이다. 이를 곧바로 PG13 전원 상태 입력으로 바꾸어 부르지 않는다.

## 6. 실물에서 연결을 확정하는 다음 시험

1. **정확한 MCU 마킹·패키지로 PG13의 다리 위치를 정한다.** PG13에서 가까운 저항·테스트패드로 이어지는 패턴을 찾는다. CN 번호나 160개 이상이라는 핀 수만으로 MCU 다리 번호를 만들지 않는다.
2. **전원·USB를 분리한 상태에서 연결을 추적한다.** PG13과 CN의 직접 연속성이 없으면 중간 저항·버퍼·트랜지스터까지 살핀다. 코팅으로 접촉하지 않은 경우와 실제 단선을 구분한다.
3. **확보한 차량측 배선도로 키 ON/OFF 조건을 재현한다.** 상시 전원과 키 연동 입력이 구분돼 있다면 상시 전원을 유지하며 키 상태만 바꾼다. 전체 전원을 동시에 끄면 GPIO 상태 판정과 펌웨어 종료 지연을 관찰하기 어렵다.
4. **같은 시간축에 후보 CN 전압, PG13 전압, UART, 화면 상태를 기록한다.** 키 ON, OFF 직후, 약 1분 뒤, 다시 ON을 대조한다. 전원 공급기에서 확인 가능한 범위의 전류 변화도 함께 남긴다. USB 연결 유무도 기록한다.

판정할 대응은 다음과 같다.

```text
키 상태 변화
 → 후보 CN/입력 회로 전압 변화
 → MCU PG13: LOW(ON) ↔ HIGH(OFF)
 → 화면·UART·전류 및 PD13/PG14/PI9 변화
```

이 연결이 확인되면 ‘해당 CN 접점은 PG13 전원 상태 입력 경로’라고 기록할 수 있다. **미분류 CN 핀에 전압을 넣거나 GND로 강제 단락하는 방법으로 찾지 않는다.** 현재는 입력과 전원 제어 출력이 함께 후보에 있기 때문이다.
