## 0.11.13: 개발자 메시지 정렬과 Bootstrap 수동 연결 확인

**NewDoe-0.11.13.apk와 NewDoe-CFW-0.11.13.zip**을 함께 사용하세요. Product도 **0.11.13**으로 업데이트해야 ODO·UART 수정이 적용됩니다. 같은 Gate를 쓰는 0.11.4 이상은 기존 CFW 업데이트 경로로 진행합니다. Gate와 B 언어팩은 그대로입니다. Bootstrap 표시 수정은 새 ZIP으로 순정에서 설치할 때 적용되므로, 그 화면만 바꾸려고 순정으로 돌아갈 필요는 없습니다.

0.11.13부터 ODO 자체 저장·보정과 이전 값 대체를 제거했습니다. 계기판 UART의 현재 유효값을 그대로 표시합니다. 수신이 끊기면 알 수 없음으로 표시하고 정상 수신 시 다시 표시합니다. 키 OFF 화면의 마지막 값은 이번 실행 중 RAM에만 남습니다. TRIP A/B·오늘/이번 주행·오일·벨트·정비 기록과 설정 보존은 유지합니다. ODO check 메뉴는 없어졌으며 예전 보정 기록은 읽거나 다시 쓰지 않습니다.

순정에서 Bootstrap 전송 검증이 끝나면 앱은 연결을 닫고 기다립니다. 상시 전원은 유지하고 순정 화면 안내에 따라 IGN을 끈 뒤, NewDoe Bootstrap 메뉴가 뜨면 IGN을 켜세요. 앱의 **현재 상태 확인**을 누르고 누도에서 **Install CFW**를 선택하세요. **Reset Bluetooth?**는 기본 **No**로 기존 페어링을 유지합니다. 앱은 같은 연결에서 이 선택을 기다렸다가 준비·검증·설치를 이어갑니다. 이제 세 번째 앱 버튼을 다시 누르지 않아도 됩니다. 이미 설치 화면에 있으면 실제 권한과 준비 상태를 확인한 뒤 곧바로 이어갑니다. 기존의 보관 데이터 복원 선택 경로는 유지하며, 이미 선택한 복원 정책도 보존합니다.

전송 검증 완료는 CFW 설치 완료가 아닙니다. 마지막 본체 설치 확인·카운트다운과 Product 정상 실행 확인은 그대로 거칩니다. 연결 실패나 미확정 설치 기록을 이유로 Bootstrap을 자동 재전송하거나 새 설치로 덮어쓰지 않습니다. 페어링이 안 되면 기존 선택형 Bluetooth 복구 안내를 따른 뒤 기기 상태를 다시 확인하세요.

개발자 메시지 원문과 페이지 조작은 그대로이며 EVE의 정렬 비트를 바로잡았습니다. 진행 표시에는 이전 기기 작업 값 대신 확인된 최신 전송량을 반영합니다. 내부 작업은 250ms 간격으로 조회하고 앱은 200ms 간격으로 표시합니다. 진행률 갱신만으로 변경 없는 설정 UI를 반복 구성하지 않습니다. 실제 Bluetooth 지연을 보장하는 수치는 아닙니다.

이번 검증은 소프트웨어 시험이며 실물 LCD·무선·설치는 시험하지 않았습니다. 모듈 전원을 유지하세요. 사용자가 앞서 수용한 구형 코드의 순정 복귀 도중 전원 중단 제한은 그대로 남아 있습니다.

## 0.10.3 · 선택해서 여는 Bootstrap 도움말

앱의 **Bootstrap에 접속이 안 되나요?**에서 Bluetooth 설정 열기 → 휴대폰의 해당 Noodoe 등록 삭제 → 본체 Bootstrap에서 UP·내 폰 선택·O를 놓고 2초 유지로 해당 키 삭제 → 폰에서 다시 페어링 → 현재 기기 확인·여기서부터 계속하기를 따릅니다. 안내를 열기만 하면 아무것도 초기화하지 않습니다. 전송·기록 중 연결 중단은 제공하지 않으며, 기존 자동 연결·Bootstrap 코드는 그대로입니다.

# 연결·페어링 복구

**APK 0.9.72 / Product 0.9.71 · 2026-10-10**

[설치 목차](README.md) · [English](12-Connection-Recovery.en.md)

## 먼저 역할 확인

0.9.72 APK와 ZIP을 사용하고 앱 기록을 유지합니다. 주행 연동을 중지한 뒤 현재 역할을 확인합니다. 순정·Bootstrap·Product는 서로 다른 단계이며 **Gate에는 Bluetooth가 없습니다**. 이미 Bootstrap이면 순정 전송부터 반복하지 않습니다.

## 응답이 끊기거나 이전 결과가 남았을 때

1. 같은 기기와 설치 ZIP을 선택하고 현재 기기/마지막 작업을 확인합니다.
2. 이전 정상 CFW로 롤백됐다고 나오면 **복귀 결과 확인 · 차단 해제**로 기기의 확인 저장까지 기다립니다. 기록을 삭제하지 않습니다.
3. 일반 업데이트나 순정 복귀를 다시 선택합니다. 상태 조회가 계속 거절되면 진단 자료를 보관합니다.
4. 앱이 제공하는 **강제 복구 후 재설치 · 데이터 유지**는 독립 순정 복구 경로입니다. 기기·부팅 상태·기록 작업·순정 복구본을 검사하며 진행 중인 쓰기를 무시하고 덮어쓰는 기능이 아닙니다.
5. 실제 순정 화면이 나오면 **본체에서 순정으로 돌아왔어요 · 확인 → Bootstrap 설치 → 보관 데이터 복원**을 따릅니다. 연결이 끊겼다는 이유만으로 복귀 완료로 판단하지 않습니다.

파일 기록·시험 부팅·복구본 오류 때문에 독립 경로도 거절되면 표시된 원인과 로그를 보관합니다. 폰이 붙지 않을 때의 [Gate 버튼 진입](10-Recovery.md)은 별도 경로입니다.

## Bootstrap 자동 연결이 안 될 때

0.9.72부터 재페어링 완료 기록을 설치 조건으로 요구하지 않습니다. Bootstrap 전송 뒤 앱이 자동 연결을 시도합니다. 이미 연결되면 그대로 계속합니다.

1. 자동 연결이 실패하면 휴대폰 Bluetooth 설정에서 **해당 Noodoe만 등록 삭제 후 다시 페어링**합니다. 앱 데이터와 설치 기록은 지우지 않습니다.
2. 앱으로 돌아와 **현재 기기 확인 → 여기서부터 계속하기**를 수동으로 누릅니다. 이전 버전의 재페어링 대기 기록은 설치를 막지 않습니다.
3. 페어링 자체가 계속 실패할 때만 본체 Bootstrap 연결 화면에서 **UP → 내 폰 선택 → O를 놓았다가 2초 유지**로 본체 쪽 등록도 지우고 다시 페어링합니다. 일반 CFW에서는 기존 **Settings → Connections → Re-pair phone**을 사용합니다. `ALL`은 모든 폰을 지우므로 필요할 때만 선택합니다.
4. 다시 **현재 기기 확인 → 여기서부터 계속하기**를 누릅니다. 앱이 삭제 순간을 확인하도록 중간에 돌아올 필요는 없습니다. **Bootstrap 파일을 다시 보내지 않습니다.**

기기 식별·선택한 ZIP·설치 파일·미확정 작업에 대한 기존 검증은 유지합니다. Bluetooth 연결만으로 설치 완료를 선언하지 않습니다. 순정에서는 순정의 페어링 조작을 사용하며 Gate에는 Bluetooth가 없습니다.

## Bluetooth 시작 오류 화면의 선택지

| 항목 | 의미 |
|---|---|
| RETRY | 현재 속도로 Bluetooth 재시작, 키 유지 |
| TRY STANDARD SPEED | Product에서 921,600baud로 재시도 |
| RESET PAIRING | 폰 키 선택/초기화 절차 |
| FIRMWARE RECOVERY | 독립 Gate 복구 메뉴 |
| DETAILS | 초기화·baud·오류·키 저장 상태 확인 |

Bootstrap은 표준 속도를 사용합니다. Product의 MCU↔Bluetooth 칩 UART 속도와 실제 무선 전송률은 다릅니다. 재페어링, 표시부 재초기화, MCU 재시작, 순정 복귀도 서로 다른 작업입니다. 설치 정지 화면의 UP+O 3초 안내는 [복구 설명서](10-Recovery.md)를 따르세요.
