# NewDoe and stock dashboard Bluetooth connections

NewDoe 1.0.1.2 connects directly to the selected dashboard using secure Classic SPP. On SR1.5 the current riding firmware registers RFCOMM channel 1 and the SPP service UUID 0x1101. The Android app shows the last confirmed stage under Device → Device connection / app theme.

## What the stock AK550 uses

On Android, the official Sunray 2.1.14 application opens a secure RFCOMM socket to the SPP service. This matches the recorded stock Android connection. The SR1.5 V5.16 OTA contains the strings `Serial Port Server Port %d (iSPP)` at file offset 0x654DC and `MFI Acc` at 0x671CA. Both full board images contain the same strings, 64 KiB later. The firmware exposes an MFi-enabled flag. Independent analysis traced an iAP2-style receive parser in the stock image. Together these observations strongly support an Apple accessory session over Classic Bluetooth on iPhone. A live stock iPhone trace is still needed to identify the protocol version actually negotiated. Other controller models have not been verified in this investigation. [Stock analysis](https://github.com/wenwen9615/Noodoe_iAP2_Discovery).

The current NewDoe riding firmware exposes generic SPP. A publicly documented iPhone API for opening an arbitrary RFCOMM/SPP socket to that service was not found. The Apple accessory route needs a manufacturer-authorized protocol and a working accessory-side authentication/session implementation. The generic Classic route exposed by Core Bluetooth uses GATT over BR/EDR, which would need a dashboard service and firmware changes. Neither path has been physically verified on NewDoe. [Apple External Accessory](https://developer.apple.com/documentation/externalaccessory/) · [Apple on GATT over BR/EDR](https://developer.apple.com/videos/play/wwdc2019/901/?time=618).
