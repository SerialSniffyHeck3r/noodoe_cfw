# 백라이트 소등 유지 조건 감사

2026-09-24. 순정 V5.16 원본 분석 및 현재 CFW 소스 대조. 장치 접근·전압 조작·설치·CFW 수정 없음.

## 결론

**확인한 순정 백라이트 경로에서 전압 임계값을 비교해 재부팅까지 점등을 금지하는 latch는 발견하지 못했다.** 순정에는 명시적 OFF/화면 정리/전원 OFF 소등이 있으며, 정상 OFF 뒤에는 같은 실행 중에 드라이버를 다시 초기화하고 켜는 경로가 있다. 전체 펌웨어의 모든 간접 호출이나 외부 LED 구동 IC의 동작까지 배제한 결론은 아니다.

반면 **현재 CFW의 백라이트 드라이버에는 오류 시 강제 종료 및 initialized=0 상태 유지가 명시적으로 있다.** 이후 밝기 설정 호출만으로는 회복하지 않으며, 별도 백라이트/표시 장치 초기화 성공이 필요하다. 이것을 재부팅만 가능한 영구 latch라고 부르지는 않는다. 이 검사 자체는 전압을 읽지 않는다.

사용자의 후속 확인: **순정 펌웨어에서 추운 날 반복적으로 발생하며, 처음 켜졌다가 바로 꺼지고 재시동하면 다시 켜진다.** PCB에서 관련 회로 블록을 식별하지 못했다고 설명했다. 엔진 시동모터 동작과 소등 시점의 일치 여부, 실제 온도·전압·PWM 파형, 재시동 후 지속 점등 시간은 아직 미확인이다. 아래 CFW 코드 차이는 이 순정 증상의 원인 증거가 아니다.

## 순정 원본과 제어 경로

- 원본 전체 dump A: `../../VERY_IMPORTANT_ORIGINAL_NOODOE_BOOTLOARDER/noodoe_full_flash_dump_A.bin`.
- SHA256: `38207bed741a8fef9e6d2ed24b86c8cb8b376ba5e4c957163f5edd83fbeb8037`.
- V5.16 OTA와 전체 dump의 APP 구간이 byte 일치함을 재확인했다.
- RAM 초기 데이터는 FLASH의 압축 데이터를 다시 복원했다. `0x20000D98` → 함수표 `0x20000CD4` → init `0x080434AE`, deinit `0x0804356C`, set `0x080435B6`.
- 주소는 MCU 실행 주소다. 전체 dump 오프셋은 `주소 - 0x08000000`이다.

상위 함수 `0x080203AA`의 인수:

| 인수 | 상태 RAM `0x200232FA` | 동작 |
|---|---|---|
| 0 | 0 | 드라이버 종료, current=0, 주기 제어 비활성 |
| 1..100 | 1 | 고정 제어값 |
| 255 (`0xFF`) | 2 | 자동 조도에 따른 목표값/주기 변경 |
| 253 (`0xFD`) | 3 | 10/90 교대 시험 제어 |
| 그 외 | 기존 상태 | 오류4 반환 |

`0x080203C4–0x0802042E`는 현재 모드가 OFF이고 새 모드가 활성인 경우 init 후 제어값50을 적용한다. `0x08020438–0x08020464`는 OFF 전환 때 deinit 후 current=0과 주기 비활성 값을 저장한다. 모드 쓰기는 성공 경로 끝 `0x080204E4`에 있다. init/set 실패는 오류를 반환하며 별도의 영구 금지 비트를 만들지 않는다.

하위 init `0x080434D6–0x080434FC`: PI8 HIGH → PC8 LOW → 3 tick 대기. deinit `0x0804358E–0x080435AE`: PC8 HIGH → PI8 LOW. PWM은 TIM5 CH4/PI0이며 이 드라이버에 전압 판독이나 PH9 조건은 없다. PH9는 별도로 확인한 버튼 입력 선택 조건이다.

직접 호출 후보 10곳을 찾았다. OFF 인수0을 명시하는 `0x080326B8`, `0x08032880`, `0x08032910`은 화면/전원 정리 경로다. `0x0801040E`, `0x08030812`, `0x0803098C`, `0x08030F28` 등은 저장된/요청된 밝기 제어값을 전달한다. `0x08030F12`는 시험 모드253이다. `0x08013E5E`, `0x08013F28`은 계산한 제어값을 전달한다. 직접 호출 검색만으로 가능한 모든 간접 호출을 열거했다고 주장하지 않는다.

기존 [전원 상태 감사](../../docs/2026-09-10-noodoe-power-state-and-sleep.md)의 PG13 OFF→`0x08032872`→백라이트 OFF도 원본과 대조했다. 디지털 전원 상태와 실제 공급 전압 임계값을 혼동하지 않는다.

## 꺼짐이 지속되는 것처럼 보일 수 있는 순정 특성

1. **현재 제어값을 캐시한다.** 수동 모드에서 같은 값을 다시 요청하면 `0x080204E8–0x080204F8`은 실제 드라이버 set 호출을 건너뛴다. 자동 모드의 주기 함수 `0x080205E2`도 current==target이면 재출력하지 않는다. 하드웨어 출력과 RAM의 기대 상태가 어긋나는 일이 별도로 생겼다면 즉시 재설정하지 않을 수 있다. 실제 그런 하드웨어 사건이 발생했다는 증거는 아니다.
2. **자동 갱신은 출력 성공과 RAM 값을 완전히 일치시키지 않는다.** `0x08020654–0x08020668`, `0x08020678–0x0802068C`는 current를 먼저 변경하고 setter의 반환값을 후속 검사하지 않는다. 오류 시 목표에 도달했다고 생각해 다음 재출력을 멈추는 가능성이 있다. 이것은 의도적인 전압 보호 latch와 다르다.
3. **센서 실패 시에는 이전 값 유지.** 기존 [조도 코드 감사](../2026-09-10-input-observations/light/README.md)의 읽기 실패/분류 실패 경로는 이전 index/목표를 유지한다. 정상 자동 테이블은10..100이고, 센서 실패를 백라이트 OFF 인수0으로 바꾸는 분기는 확인하지 못했다.

하위 setter는 PWM stop/config/start를 수행한다. `0x08043626`에서 start 함수를 호출한 뒤 반환값 r0 대신 이전 r5를 검사하는 코드도 보인다. 다만 해당 HAL start 함수의 도달 가능한 실패 여부를 이번에 검증하지 않았으므로 이 명령만으로 실제 고장 원인이나 발생 가능한 버그라고 단정하지 않는다.

## 전압 감시 단서의 범위

APP 벡터의 PVD IRQ는 `0x08076E00`, ADC IRQ는 `0x08076E34`의 자기 자신으로 분기하는 기본 핸들러다. 별도 백라이트 보호 처리기는 아니다. APP의 반워드 정렬 literal 검색에서 ADC 레지스터 범위 `0x40012000..0x400123FF` 값은 검출되지 않았다. 이 두 결과는 직접적인 ADC/PVD 기반 소등 정책 근거가 없다는 보조 단서다. 주소 합성/폴링/외부 전압 검출 핀/차량 통신/LED 드라이버 자체 보호의 부재까지 증명하지 않는다.

부트로더의 기존 [백라이트 분석](../2026-09-22-bootloader-display/README.md)과 `0x2000516E` 상태 함수도 비교했다. 알려진 설치/실패 표시는 고정 제어값50을 사용하며, 해당 상태 함수 역시 OFF/고정/특수 모드와 드라이버 호출로 구성된다. 이 한정 경로에서 전압 임계값 latch는 확인하지 못했다.

## 현재 CFW의 명시적인 오류 후 소등 유지

프로젝트: `../../STM32CubeProjects/FuckNudo_Noodoe_CFW_Project`.

`Drivers/BSP/src/bsp_backlight.c:126`의 `BSP_BacklightSetPercent()`는 다음 중 하나면 `BacklightFail(HAL_ERROR)`를 호출한다:

- initialized==0 또는 인수>100.
- TIM5 PSC!=1679 또는 ARR!=99.
- TIM5 CEN==0 또는 CC4E==0.

`BacklightFail()`(57행) → `BSP_BacklightShutdown()`(42행) → PC8 HIGH, PI8 LOW, PI0 GPIO LOW, timer/channel 정지, **initialized=0** 및 **stage=0x80000000**.

따라서 한 번 실패하면 다음의 올바른 밝기 설정 호출도 initialized==0 때문에 다시 실패한다. 단순 밝기 변경으로는 풀리지 않는다. `BSP_BacklightInit()`(65행)을 성공시키는 경로가 필요하며, 이 함수는 재부팅 외에도 표시 장치 초기화에서 호출될 수 있다. 순정에 이런 latch가 있다고 확대하지 않는다.

초기화 중 ISR/IRQ 마스킹 상태, 기대와 다른 타이머 클록/설정, PWM 시작 실패도 같은 오류 종료 경로다. 모두 코드가 검사하는 소프트웨어/레지스터/HAL 조건이며 전압 수치 조건은 아니다. BSP_Display의 상위 공개 API는 인수>100을 드라이버 호출 전에 거절하므로 일반 호출에서 이 오류가 반드시 강제 소등으로 이어진다고 일반화하지 않는다.

`Graphics/Port/src/graphics.c:344`의 assert 실패 경로도 확인했다. 등록된 fatal handler가 처리할 기회가 있으며, 그 뒤로 진행하면 표시 장치를 종료하고 무한 대기한다. 워치독/프로필/fatal handler의 후속 동작까지 무시하고 무조건 수동 재부팅만 가능하다고 표현하지 않는다.

## 재현과 진단 기준

[verify.py](verify.py)는 원본 Thumb의 모드/램프 제어를 실행하고 드라이버/센서 임계값 함수 경계만 성공/오류 stub으로 대체한다. **8개 시나리오 통과**: 3개 활성 모드 각각 ON→OFF→ON, init/set의 일시 오류 후 재시도, 동일 수동값의 출력 생략, 자동 모드의 목표 도달 후 출력 생략, 자동 모드의 마지막 단계 setter 오류 후 재시도 생략. 마지막 시험은50→51 변경에서 setter가0x21을 반환해도 current=51이 되고, 오류를 제거해도 후속200회 주기 처리 동안 set 호출이0회임을 확인했다. 실제 전압/광학 밝기/PWM 파형 시험이 아니다. 결과와 읽은 CFW 소스 해시는 [verification.json](verification.json)에 있다.

실제 증상을 좁힐 때는 소등 당시 TIM5 CEN/CC4E/CCR4, PC8/PI8 및 소프트웨어 상태를 함께 비교할 수 있다. CFW라면 `g_bsp_backlight.stage/result/initialized`가 우선적인 근거다. 소프트웨어가 꺼짐을 명령한 경우와, 점등을 명령 중인데 실제 빛이 없는 경우를 구분해야 한다. 이번에는 장치에서 이 값을 읽지 않았다.

## 후속: 추운 날 점등 직후 소등·재시동 복구

이 양상은 점등 후 드라이버 보호 정지/기동 실패/제어 중단을 우선 조사할 근거다. 의도적인 저온 차단 정책이나 특정 부품 고장을 확정하는 근거는 아니다. 재시동은 MCU뿐 아니라 PI8/PC8 및 PWM 초기화 경로도 다시 실행하므로 하드웨어 보호 해제와 소프트웨어 상태 초기화 양쪽 모두와 양립한다.

일반 부품의 동작을 설명하는 공식 자료이며 누도에 이 부품이 실장됐다는 뜻은 아니다:

- [TI TPS61165 데이터시트](https://www.ti.com/lit/ds/symlink/tps61165.pdf), §8.3.2: LED 단선/출력 과전압 조건이 유지되면 내부 스위치를 끄고 CTRL 재활성화까지 정지한다. 보호회로는6핀 IC 내부에 포함된다. §8.3.3의 저전압 정지는 전압 회복 후 자동 재시작하므로 **모든 저전압 보호가 재시동을 요구한다**고 일반화하면 안 된다. 누도 구동 IC 형번은 미식별이다.
- [Analog Devices LED 특성 설명](https://www.analog.com/en/resources/technical-articles/2022/07/16/08/08/leds-are-still-popular-and-improving-after-all-these-years.html): 같은 전류에서 LED 순방향 전압은 저온에서 높아지는 경향이 있다. 직렬 LED의 요구 전압 상승이 구동 전압 여유를 줄일 수 있으나, 누도의 LED 개수/전압 여유/보호 임계값은 모른다.
- [TI 자동차 백라이트의 cranking 대책](https://www.ti.com/lit/an/snva681a/snva681a.pdf): 엔진 시동 때의 배터리 전압 강하는 백라이트 전원 설계의 실제 고려 사항이다. 자료의 자동차 시험 전압·시간을 AK550 실측값으로 사용하지 않는다.
- [Panasonic 전해 커패시터 저온 특성](https://industrial.panasonic.com/kr/ds/ss/technical/lc4): 일반 알루미늄 전해 커패시터는 저온에서 ESR이 증가해 리플 억제 성능이 낮아질 수 있다. 해당 회로에 그 종류의 커패시터가 있는지부터 확인해야 하며 모든 커패시터를 같은 특성으로 취급하지 않는다.

가장 구분력이 큰 관측은 소등 직전/직후의 PI0 PWM과 PI8/PC8 제어, 구동부 입력 전원이다. MCU 측 파형이 정상 유지돼도 IC 입력까지의 연결은 추가 확인 대상이다. 전원과 점등 명령이 구동부까지 정상 도달하는데 LED만 꺼지면 구동부/LED 경로를 우선한다. 제어 신호가 먼저 꺼지면 앱 상태·전원 입력·초기화 실패를 추적한다. PCB에서 보호회로가 별도로 보이지 않는 것만으로 보호 기능의 부재를 판단할 수 없다.
