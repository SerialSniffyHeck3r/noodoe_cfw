# 키로수칸 하단 디바이더와 오일 잔량선 — 2026-09-13

키로수칸 아래에 기존과 같은 두께·색상의 사다리꼴 구분선을 추가했다.
기존 오일 호는 이 선 아래의 가로 잔량선으로 교체했다. 실제 장치에 설치했고,
EVE 화면 캡처를 통해 배치와 잔량 상태를 확인했다.

- 기존 위 구분선: (92,422) → (116,403) → (364,403) → (388,422), 유지.
- 새 아래 구분선: (102,427) → (126,446) → (354,446) → (378,427).
- 오일 잔량선: x145, y454, 190×4px. 유효한 잔량에 따라 왼쪽부터 채운다.
- 20% 이하 주황색, 그 위 청록색. 유효한 0은 빈 적색 트랙,
  미확인은 빈 중성색 트랙이다. 기존 비율·유효성·색상 조건을 유지했다.
- ODO/TRIP/RESV에서 잔량선을 표시하고, OIL/BELT/SERV에서는 숨긴다.
  OIL의 HOURS와 BELT/SERV의 DAYS는 기존 위치와 계산을 유지한다.
- 모드·아이콘·숫자·단위·시계·중앙 콘텐츠 영역의 위치와 크기는 유지했다.
  숫자와 km/mi의 실제 글자 하단은 모두 y436이다.

## 설치와 읽기 검증

APP만 0x08010000에 기록했다. 순정 부트로더·설정이 있는 하위 64KiB는 보존했다.
최초 CubeProgrammer 내장 검증에서 주소 0x08029058의 읽기 불일치가 발생했다
(읽기 0x60, 예상 0x4F). 이 실패 로그는 `install/`에 그대로 보존했다.

재기록하지 않고 정지 상태에서 APP 전체를 두 번 독립적으로 읽었다.
두 읽기 모두 설치 파일과 바이트 단위로 완전히 일치했고, 하위 64KiB도 설치 전
사본과 같았다. 결과는 `recovery-read/results.json`에 있다. 최초 불일치의
물리적 원인은 확정하지 않았다.

그 뒤 `bringup.py --test-only --cycles 2`가 통과했다. 순정 BL을 통한 두 번의
재부팅과 HAL/RTOS 진행을 확인했다. `install-verified/summary.json`을 참조한다.
원래 디버그 동결 레지스터 값 0을 복원하고 읽어 확인했다
(`install-verified/restore-original-debug-freeze.log`).

## 실제 화면 검증

`verify_preview.py`로 아래 여섯 경우를 캡처하고 실제 픽셀을 검사했다.

- OIL HOURS: 잔량선이 숨겨지고 기존 시간 글자가 표시됨.
- ODO 잔량 0%, 20%, 75%, 100%: 트랙·채움 길이·색상이 기대값과 일치.
- ODO 잔량 미확인: 채움 없이 중성색 트랙만 표시됨.

모든 경우에서 새 아래 구분선, 기존 호 제거, 글자 하단 정렬을 확인했다.
전체 480×480 캡처에서 기존 중앙 문구와 위쪽 구분선도 확인했다.
시험 전후 실제 카드·거리 모드가 보존되고, 미리보기가 해제됨을 확인했다.
RTC 설정 호출은 없었으며, 실제 IGN ON 누계는 증가하고 누락 카운터는 0이었다.

최종 결과는 `preview/results.json`의 `status: pass`이다.
화면 결과와 별개로 이 기판의 설정 저장소는 여전히 미프로비저닝 상태다.
이번 검증은 오일 시간 누계의 영구 저장 완료를 의미하지 않는다.
