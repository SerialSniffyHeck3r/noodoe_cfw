# UP 버튼 입력 진단 — 2026-09-12

## 현재 결론과 사용자 정정

사용자가 **순정 펌웨어에서도 UP 버튼이 반응하지 않는다**고 명확히 정정했다. 스코프에서 정상적인 active-low 변화를 확인한 위치는 **하네스/커넥터 쪽**이며 MCU 핀은 아니었다. 따라서 하네스 신호가 정상이라는 사실만으로 MCU PD12까지 정상적으로 전달된다고 판단할 수 없다.

커스텀 화면에서 UP의 눌림·long·very-long 세 칸이 켜지는 현상은 MCU가 UP을 LOW로 읽는 경우와 일치한다. 이후 두 차례 읽기 전용 폴링에서도 PD12는 수집한 모든 샘플에서 LOW였다. 샘플 사이의 짧은 전이를 전수 관측한 결과는 아니다.

사용자의 **최종 정정은 “아까 실험에서 누른 게 엔터였고 내림을 안 눌렀다”**이다. 따라서 기존 UP=PD12 / ENTER=PA15 / DOWN=PI6 매핑을 유지한다. 처음의 DOWN 누름 진술을 근거로 ENTER/DOWN을 바꾸지 않는다.

## 확인된 버튼 핀

대상은 STM32F429 계열의 **LQFP176** 패키지다. GPIO 이름, 패키지 핀 번호, 하네스 번호를 혼용하지 않는다.

| 역할 | MCU GPIO | LQFP176 핀 번호 | 순정 설정 |
|---|---|---|---|
| UP | **PD12** | **100** | LOW 눌림, 입력, 내부 pull 없음, 양에지 EXTI |
| ENTER | PA15 | 138 | 동일 |
| DOWN | PI6 | 175 | 동일 |

공식 패키지 근거는 [ST STM32F427xx/STM32F429xx datasheet DS9405 Rev 13](https://www.st.com/resource/en/datasheet/stm32f429ig.pdf)의 Figure 14(p.48, LQFP176 top view) 및 Table 10이다. PD12는 p.63, PA15는 p.67, PI6는 p.71의 **LQFP176 열**에서 확인했다. 다른 패키지 열의 번호를 적용하면 안 된다.

순정 역할은 FLASH descriptor `0x08076D98 = 3C 0F 86` → EXTI 처리 `0x08043A44–0x08043A72` → short 이벤트 3/4/5 → OQC serializer `0x08029CDA–0x08029D14` → APK UP/ENTER/DOWN bit 이름으로 연결된다. 자세한 경로와 원본 해시는 [순정 버튼 분석](../2026-09-12-buttons-bringup/stock-buttons.md)에 있다.

revision 분기 `0x08036DEE–0x08036DF0`는 revision 3 미만에서 PI2/4/5 설정을 건너뛰고 **공통 PD12 초기화 `0x08036E7A`로 합류**한다. 이 버튼 매핑이 revision별로 달라진다는 근거는 발견하지 못했다.

## SWD로 읽은 현재 설정

root가 읽기 전용으로 확보한 `live-gpio-read.log`의 값과 해석이다. 이 문서 작성자는 장치에 접근하지 않았다.

| 레지스터 | 읽은 값 | 관련 해석 |
|---|---|---|
| GPIOD MODER | `0x04003000` | PD12 MODER[25:24]=00, GPIO 입력 |
| GPIOD PUPDR | `0x00000000` | PD12 내부 pull-up/pull-down 없음 |
| GPIOD IDR | `0x0000EFBB` | bit12=0: **스냅샷 당시 UP LOW** |
| GPIOH IDR | `0x000022BC` | bit9=1: **PH9 HIGH** |
| EXTI IMR / RTSR / FTSR | 각각 `0x00009040` | 버튼 line6/12/15 interrupt와 양에지 설정 |

현재 PD12가 출력으로 잘못 구동되거나 내부 pull-down으로 설정됐다는 증거는 없다. PH9도 이 스냅샷에서는 HIGH다. 단, 이 값들은 MCU 디지털 입력과 설정이며 핀 전압의 아날로그 파형을 대신하지 않는다.

## 연속 폴링과 최종 조작 확인

1차 [result.json](gpio-poll-20260912-095236-639093/result.json)은 90.438초, 141샘플, 읽기 오류 0건이다. PD12는 141개 모두 LOW, PA15는 LOW 6개/HIGH 135개, PI6는 141개 모두 HIGH였다. PA15에서 한 차례 LOW→HIGH 복귀가 관측됐다. 사용자 최종 정정에 따라 이 변화는 ENTER 조작과 일치하며, **DOWN은 1차 실험에서 누르지 않았으므로 PI6의 HIGH 유지로 DOWN 고장을 판정하지 않는다.** 원문 정정과 해석은 같은 폴더의 [operator-confirmation.json](gpio-poll-20260912-095236-639093/operator-confirmation.json)에 보존되어 있다.

2차는 약 61초/62샘플이며 PD12가 모두 LOW, PA15와 PI6는 각각 한 샘플 LOW였다. 그러나 사용자는 2차 누름 순서를 확인하지 않고 1차 진술을 정정했다. 따라서 **2차의 각 LOW 샘플을 특정 물리 버튼 조작에 귀속하거나 매핑 검증 성공으로 해석하지 않는다.** 해당 실행 폴더의 operator-confirmation.json도 이 한계를 기록한다.

관측은 HOTPLUG SWD로 GPIO IDR을 순차적으로 읽은 값이다. 아날로그 파형·접점 바운스·부품 종류를 측정한 결과가 아니다. 이 진단 중 코드·펌웨어·핀 매핑은 변경하지 않았다.

## 순정 무반응과 커스텀 세 칸이 양립하는 이유

순정은 **허용된 에지가 발생해야 일반 버튼의 누름 시각을 시작**한다. EXTI 콜백 `0x08043A16–0x08043A32`는 PH9 HIGH 및 IGN ON 캐시 `0x20023302 != 0`을 요구하고, 이후 LOW를 읽으면 `0x20022F30`의 해당 down 시각을 기록한다. 주기 처리 `0x08043E4C–0x08043E56`는 down=0인 버튼을 건너뛴다.

순정 startup zero-init descriptor `0x08075548`는 루틴 `0x0801FCAA`로 `0x20000E10`부터 `0x22504` byte를 0으로 만든다. UP down/up 변수 `0x20022F30` / `0x20022F40`도 이 범위에 들어간다. IGN ON 때 부팅 상태를 직접 읽는 특수 처리는 **ENTER+DOWN 조합**뿐이며 UP이 아니다 (`0x08043D94–0x08043DDA`). 따라서 UP이 초기화 전부터 LOW이고 허용된 새 에지가 없다면 순정에서 아무 이벤트도 만들지 않을 수 있다.

커스텀 `BSP_Buttons_Init()`은 시작할 때 각 GPIO를 읽고, 이미 LOW인 버튼도 현재 시각부터 후보로 기록한다. 이후 press debounce 21ms, long 2001ms, very-long 3000ms를 통과하면 LCDTest의 해당 칸들이 켜진다. PH9/IGN gate는 저수준 버튼 진단에 적용하지 않는다. 따라서 **같은 LOW 상태가 순정에서는 무반응, 커스텀에서는 계속 눌림 표시**로 드러날 수 있다. 이것은 핀 매핑을 바꿀 근거가 아니라 입력 시작 방식의 차이다.

## 떨어진 소형 부품과 다음 확인

사용자는 MCU의 대략 110–120번 부근에서 0402로 보이는 소형 부품이 떨어졌다고 알렸다. 정확한 부품 종류·값·원래 위치·연결 net은 미확정이다. 이를 UP의 직렬 저항, pull-up, 커패시터 중 하나라고 확정하거나 임의 값으로 대체할 근거는 아직 없다. 육안상 가까운 위치만으로 PD12 신호와 연결됐다고 판단하지 않는다.

사용자가 MCU 100번 다리에 프로브를 대기 어렵다고 했으므로, root는 MCU 핀에 직접 프로브를 대는 대신 위의 읽기 전용 SWD GPIO 관찰을 수행했다. 하네스의 정상 변화와 MCU PD12의 관측 LOW를 종합하면 하네스 측정 지점에서 MCU 입력까지의 연결·주변 부품·핀 자체 상태를 우선 좁혀야 한다. 이 사실만으로 MCU 손상이나 떨어진 부품의 종류를 단정하지 않는다.

- 하네스는 변하지만 PD12 bit12가 계속 0이면, 하네스 측정 지점에서 MCU 입력까지의 연결·주변 부품·핀 자체 상태를 우선 좁힌다. 그 사실만으로 MCU 손상이라고 단정하지 않는다.
- PD12 bit12가 정상 HIGH/LOW로 바뀌는데 화면만 고정이면, 버튼 BSP 상태와 표시 경로를 별도로 대조한다.

1차는 사용자의 최종 정정과 함께 해석하고, 조작 순서가 확인되지 않은 2차는 GPIO 관측값으로만 보존한다. 진단을 위해 펌웨어, 플래시, 옵션 바이트를 변경하지 않는다.
