# 0.9.69 · 설정 목록 조회 오류 수정

CFW 업데이트에서 **Device rejected opcode 151 result=3**이 나오면 **앱 데이터를 지우지 않고 0.9.69 APK를 덮어 설치**한 다음, 같은 **0.9.69 ZIP**을 선택해 정차 상태에서 CFW 업데이트를 다시 진행하세요. 최초 설정 백업 단계에서 실패했다면 이번 시도의 리소스·Product 전송은 아직 시작되지 않았습니다. 설치 기록은 유지하고, 이전에 전송 중 끊긴 작업이 있다면 먼저 현재 CFW / 설치 결과 확인을 사용하세요.

기존 펌웨어는 알림 표시 시간 항목을 저장 목록에 남겨 두면서 메뉴의 설명 항목을 제거했습니다. 그래서 설정 목록 첫 페이지 전체가 거부되었습니다. 배포한 0.9.68의 ARM 코드를 실행해 재현했으며, NOR 플래시의 물리적 손상을 뜻하는 오류가 아닙니다. 같은 누락으로 기존 설정 파일의 로딩도 거부될 수 있었습니다.

새 앱은 이 구버전 구조를 확인하고 업데이트 상태가 대기 또는 실패 상태일 때만, 누락 항목 앞의 설정 네 개를 기존 개별 읽기 명령으로 조회합니다. 나머지 목록은 정상 조회하여 기기·대상 펌웨어와 결합된 설정·이름 백업을 전송 전에 저장합니다. 실제 업데이트 진행 중, 다른 오류, 알 수 없는 형식이나 불완전한 읽기는 그대로 중단합니다. 새 Product는 옛 시간 항목을 숨겨진 읽기 전용 항목으로 유지합니다. 메뉴나 팝업 시간은 바꾸지 않습니다.

업데이트 후 정상 부팅이 확정되면 설정 비교·복원·저장 완료 응답·재확인을 진행합니다. 완료까지 앱 데이터를 유지하세요. NOR의 사진·트립·정비 기준점은 기존 업데이트 보존 절차가 담당하며, 이번 설정 백업은 전체 NOR 덤프가 아닙니다. 0.9.68의 속도 링과 정보 공유 기능은 유지합니다.

F4 순정 5.14 / 5.16 허용 조건, Bootstrap 수동 재페어링과 기존 복구 절차는 같습니다. Gate·Bootstrap·순정 복구·리소스·진단·삭제 이미지는 동일합니다. Stage 6/4에서 재시작을 요구하면 **UP + O를 동시에 3초** 누른 뒤 재연결하여 결과를 확인하세요. 수동 재시작 제한 자체를 해결한 버전은 아닙니다.

검증: 배포 ARM 코드 재현·새 ARM 설정 목록 검사, Android 설정 백업·구버전·오류 테스트, Debug/Release/APK 빌드, Product 해시와 APK 서명 대조. 실차·무선 실기 검증은 하지 않았습니다.
