# 순정 펌웨어 어셈블리에서 하드웨어 브링업 정보를 읽어낸 방법

이 문서의 질문은 “순정 펌웨어가 업데이트를 어떻게 하는가”보다 앞선다. **이 보드의 MCU는 어떤 계열이고, 어떤 주변장치와 외부 칩이 연결되어 있으며, 그걸 새 BSP에서 어떻게 안전하게 다시 켜는가?** 순정 V5.16의 Thumb 명령, 복원한 초기 RAM 데이터, 순정 앱의 통신 코드와 실기기 관찰을 어떻게 조합했는지 설명한다. [English](stock-assembly.md)

## 먼저 “명령어가 맞는지” 확인했다

순정 OTA APP는 458,748바이트이고 MCU 주소 **0x08010000**부터 로드된다. 처음 두 워드는 초기 MSP **0x20025318**과 Reset 벡터 **0x08076719**다. ARM Cortex-M의 벡터 맨 끝 비트는 Thumb 상태를 뜻하므로 실제 명령 시작은 0x08076718이다. APP의 SystemInit 0x08073E90은 VTOR을 0x08010000으로 바꾼다. 이 사실은 APP의 링커 시작점과 인터럽트 테이블 위치를 결정한다. 0x08000000–0x0800FFFF는 OTA APP에 포함되지 않는다.

이후 각 후보 함수를 다음 순서로 읽었다.

1. 벡터·직접 호출·분기에서 함수 경계를 찾는다. ARM Thumb는 16/32비트 명령이 섞이고 PC 상대 리터럴 풀이 코드 사이에 있으므로, 임의 주소부터 연속으로 분해한 모든 줄을 명령으로 해석하기엔 좀 꼬롬했다. ㅋ
2. STM32F4의 **주변장치 기준 주소**를 리터럴에서 찾는다. 예를 들어 0x40013000은 SPI1, 0x40000C00은 TIM5다.
3. 핸들 구조체에 기록하는 상수의 오프셋을 HAL 구조체와 대조해 모드·데이터 비트·클록 분주기·DMA 채널을 복원한다. GPIO는 포트 기준 주소, 핀 마스크, Alternate Function, 출력 레벨과 **실제 호출자**를 같이 확인한다.
4. 외부 칩은 JEDEC ID, 제조사 고유 명령, 펌웨어 패치 바이트, 표시 칩의 REG_ID처럼 다른 제조사 자료와 맞는 **식별값**을 찾는다.

예외 벡터도 함정이었다. 많은 벡터가 APP 안의 주소를 가리키지만 그 끝은 IAR의 기본 무한 루프 명령 **FF F7 FE BF**뿐이다. 주소가 있다는 이유만으로 SPI1 IRQ나 I2C3 IRQ가 실사용된다고 판단하지 않았다. 확인된 비기본 IRQ에는 UART5, 관련 DMA, TIM2/TIM5, 여러 EXTI, OTG_HS 등이 들어간다. 이는 첫 BSP에서 어떤 경로를 폴링·바이트 IRQ·DMA로 만들어야 할지 정하는 데 중요하다.

## MCU 계열과 메모리부터 좁힌 근거

일단 이게 엄청나게 커다란 근거이자, 내가 '커스텀 펌웨어를 개발해야겟다' 라는 마음가짐을 바로 갖게 된 중요한 단서가 되었다. 당연하지. STM32면 솔직히 게임 오바 아니겠냐?

벡터 순서, Cortex-M4 FPU 명령, GPIO/USART/SPI/FMC 레지스터 주소, ST HAL의 핸들 배치가.. 다름아닌 **STM32F429 계열**과 맞았다. 이것은 내가 여러 번 사용해본 칩의 라인업과 동일하다. 그 뿐만이 아니였다! 초기 스택 주소와 내부 플래시 크기도 그 구성과 양립한다. 이후 실물 전체 플래시 두 번 읽은 512KiB가 바이트 단위로 일치했고, APP 영역은 보존한 V5.16 OTA와 일치했다.

## 외부 장치별로 어떻게 알아냈나

| 장치·버스 | 어셈블리에서 찾은 근거 | 새 코드의 첫 브링업과 아직 남은 경계 |
|---|---|---|
| **FT81x EVE / SPI1** | SPI1 핸들 생성 함수 0x08033C1A, Instance 0x40013000, master·8비트·mode 0·software NSS. 0x0801FD2E 호출자는 DIV8, 0x0801FF84는 DIV4를 넘긴다. GPIO MSP 0x080373F2–0x08037426은 PB3/PA6/PB5 AF5에 맞는다. EVE의 REG_ID 주소 0x302000과 값 0x7C, command FIFO 주소가 FT81x 자료와 맞는다. | 저속 SPI로 REG_ID를 먼저 읽고 EVE 준비·480×480 타이밍·RAM_G·디스플레이 리스트를 차례로 켠다. FT810/811/812/813 중 정확한 세부형은 모르지만 사실 화면만 켜지면 만사 OK이다. |
| **EVE 선택·리셋 후보** | 0x08033D00–0x08033D0E은 SPI 거래 직전에 GPIOA mask 0x10을 LOW로 만들어 **PA4 CS** 해석을 뒷받침한다. 0x08034140–0x0803419A은 GPIOB mask 0x02를 LOW→지연→HIGH 등으로 바꾸고 EVE 초기화 호출자 0x0801FD22가 인수 1을 준다. | PA4를 거래 선택으로, PB1을 EVE PDN/reset 후보로 좁혔다. |
| **외장 NOR / SPI5** | PF7/8/9 AF5와 PF6 GPIO 선택, SPI5 master 8비트 mode 0. 플래시 드라이버는 9F RDID 뒤 **C2 20 1B**를 검사하고 128MiB·4KiB 소거·256바이트 페이지를 가정한다. 이 값은 Macronix MX66L1G45G 자료와 맞는다. SPI5 MSP 0x0803750A–0x08037616은 DMA2 Stream4 TX / Stream3 RX, Channel2를 실제 SPI 핸들에 연결한다. |  |
| **LCD 제어 / SPI4** | PE2/PE5/PE6 AF5, 16비트 master·mode 0·DIV16 설정과 10/11/28/29/0A 명령 계열이 보인다. | EVE가 픽셀 렌더링을 맡고 SPI4는 별도 패널 제어로 다룬다. |
| **차량 데이터 / UART5** | PC12 TX·PD2 RX AF8, 115200 8N1. UART5 IRQ 0x08070E68→HAL IRQ 0x0804C25C→RXNE 0x0804C55C→수신 완료 0x08043C08→F5 파서 0x0804EA14로 이어진다. DMA1 S0/S7 설정도 있지만 이 파서는 **RXNE 바이트 IRQ**에서 실행된다. | 먼저 수신 전용으로 F5/명령/길이/페이로드/XOR를 파싱해 실제 속도·ODO와 대조한다.. |
| **Bluetooth / USART1** | PA9/10/11/12 AF7와 RTS/CTS, DMA2 S5/S7 Channel4. 순정 이미지에는 TI CC256x 제조사 HCI 명령과 서비스 팩 바이트, Bluetopia/SPP 코드가 있다. USART1 baud는 초기값을 쓴 뒤 호출자에 따라 바뀐다. | 호스트가 HCI UART로 칩을 초기화·패치한 뒤 SPP를 올린다는 구조를 재현한다. |
| **조도 / I2C3** | PH7 SCL·PC9 SDA AF4 오픈드레인, 400kHz와 7비트 주소 0x45 경로. 드라이버의 제조사/장치 ID 0x5449/0x3001과 레지스터 사용이 OPT3001을 가리킨다. | 처음에는 주소 ACK와 ID 읽기를 수행한 뒤 조도값·자동 밝기 정책을 검증한다.  |
| **백라이트 / TIM5** | 0x0804351A–0x0804363C은 TIM5 Instance 0x40000C00, ARR 99, 약 50kHz 카운터 목표, CH4 PWM1 active HIGH와 듀티 제한을 보여준다. GPIO MSP 0x08038224–0x08038240은 **PI0 AF2**다. | TIM5_CH4 PWM을 별도 백라이트 서비스로 만들고 낮은 듀티부터 실제 밝기·극성을 확인한다. |
| **버튼·IGN·선택 스위치** | GPIO 포트·핀 마스크 초기 데이터와 EXTI 호출, TIM2의 주기적 읽기, 순정 입력 허용 조건을 함께 대조했다. PD12/PI6/PA15는 세 액티브 LOW 버튼, PG13은 IGN, PH9는 계기판/누도 조작 선택으로 좁혀졌다. | GPIO 원시값→디바운스→버튼 시간 이벤트→PH9/IGN 정책→화면 동작 순으로 분리한다.  |

FT81x나 NOR처럼 **ID·명령 체계가 부품 자료와 일치**하면 계열 판단이 강해진다. 반대로 SPI4의 패널 품번, SDRAM 칩 표기, MCU 패키지, Bluetooth BGA의 실제 실장 리비전은 초기화 코드만으로 확정할 수 없다. I2C1에는 MFi 인증칩으로 해석되는 경로도 보였지만 CFW 브링업 대상에서 제외했다. 우선 나는 애플 회사를 광적으로 싫어하기 때문이며, 내가 설령 애플을 좋아한다고 해도, 난 그 비싼 아이폰을 보유하고 있지 않고 애플용 앱을 개발하는 법을 모른다.
