# 컴패니언 음악·사진·GPS / CFW 6.2 (2026-09-22)

이번 변경은 코드·빌드·호스트/ARM 시험까지 완료했다. 새 APK/펌웨어는 실제 폰이나 누도에 설치하지 않았다. ADB에 연결된 폰이 없었으며, 실제 CJK 화면·RF 전송속도·29fps·장시간 안정성을 이번 시험으로 확인했다고 주장하지 않는다. 전체 역사적 컴패니언 계획의 모든 기능이 완료된 상태도 아니다.

## 음악 표시

- Android `PhoneVisualRenderer`가 시스템 글꼴 fallback과 StaticLayout으로 한글·일본어·중국어의 실제 글자 배치를 처리한다. 고정 304×72 영역 안에서 제목은 굵게 32→22px, 아티스트는 보통 24→18px로 맞춘다. 두 줄은 각각 수평 중앙 정렬하며, 한 줄 길이를 넘으면 끝을 말줄임한다. 스크롤하지 않는다. 문자열은 NFC 정규화하고 제어문자를 제거한다.
- 두 줄을 함께 4bpp 투명도 이미지 10,944B로 전송한다. 글자가 바뀔 때만 보내며 매 프레임 보내지 않는다. GPU는 흰색/회색 커버리지로 표시하므로 배경과 자연스럽게 합성한다.
- 앨범 아트는 정사각형 중앙 crop, 480×480 baseline JPEG, 최대128KiB다. 기기에서 RGB565로 완전히 디코드한 후 기존 공용 배경 렌더러에 전달한다. 음악 이외 페이지에서는 설정된 사진을 사용한다. 재생 진행바/시간과 물리 재생·일시정지/이전·다음 버튼은 유지한다.
- 곡 키가 바뀌면 새 페이지 세대가 된다. 두 개의 고정 텍스처를 재사용하며, 이전 표시 목록의 swap 완료 뒤에만 다시 쓴다. 정지된 곡의 문자가 늦게 도착한 경우에도 화면을 무효화해 표시한다. 동일 키의 다른 마스크를 허용하지 않는다.
- 매번 새 Bitmap 객체가 생성되었다는 이유로 전송을 반복하지 않는다. 샘플링한 아트 내용·곡 식별자·제목·아티스트·길이로 변경 여부를 결정한다. 샘플 기반 아트 비교는 암호학적 동일성 증명이 아니다.

## 전송·사진·GPS·범위 변경

- NDCP capability0x100, 0x79–0x7C를 추가했다. 최대960B 청크, 연결 세대/키/순서/전체 CRC를 검사한다. 수신 parser는 비동기 요청만 접수하고 StorageTask가 제한된 단위로 CRC/JPEG/영구 저장을 수행한다. 자세한 형식은 `NDCP-VISUAL.md`.
- 폰 사진 선택기로 CFW 슬롯0/1/2를 바꿀 수 있다. EXIF 회전과 크기 제한을 적용한다. 기존 PhotoStore의 A/B 기록·물리 readback·전체 디코드 검증이 끝나야 폰에 저장 성공을 표시한다. 사진 업로드 동안 일반 연동을 중지해 단일 소켓 소유권을 지킨다. 순정 사진을 APK에 넣거나 덮어쓰지 않는다.
- 음악/앨범아트는 RAM에만 둔다. 이미지 전송 큐는 현재 작업과 최신 제목/아트 두 항목으로 제한한다. 완료 대기는120초 상한이며, 모호한 FINISH를 맹목적으로 반복하지 않는다. 빠른 이미지 pump에서도 재연결 안정화는 반복 횟수가 아닌 실제60초로 판단한다.
- `SESSION_START`에서 GPS 궤적을 초기화한다. 확정 종료 이전의 짧은 IGN 흔들림은 같은 세션으로 유지한다. 단순10초 수신 공백으로 궤적을 지우던 동작을 제거했다. 폰은 새 세션 이전 위치·5초 이상 오래된 위치·동일 위치 샘플을 재전송하지 않는다. GPS는 IGN ON에서만 수집하고 UART 속도를 대체하지 않는다. 수신 공백 양끝을 별도 선분으로 분리하는 로직까지 추가한 것은 아니다.
- 독립 휴대전화 리모트 페이지와 이벤트를 제외했다. 음악 제어는 유지한다. 메뉴 ID는 프로토콜/저장 호환성 때문에 재번호화하지 않고0,1,2,3,6,7만 사용한다.

## 설치 후 일상 업데이트

- CFW 버전6.2 패키지를 만들었다. 기존의 독립 Gate와 Bootstrap 바이트는 그대로 유지하며 이전 ZIP과 직접 비교했다. 일상 업데이트는 같은 Gate/호환 자산을 확인하고384KiB Product APP를 보낸다.
- 상태 길이84B, 전송 트랜잭션 ID, DATA 확인 위치, FINISH의 전체 길이/해시, COMMIT 상태를 검증한다. 다른 진행 중 작업은 덮어쓰지 않는다. 기존4KiB 체크포인트 재개, COMMIT 불명확 시 상태 조회,60초 정상실행 및 앱 확인, 자동 롤백 정책은 유지한다.
- 새 Gate나 다른 자산을 요구하는 업데이트를 일반 APP 업데이트로 처리하지 않는다. 현재 실행 중인 Bootstrap에는 최초 사용한 ZIP의 Bootstrap 해시가 일치해야 한다. 최신 ZIP이라는 이유로 일치 검사를 우회하지 않는다.
- 정상 업데이트 확정 시 설정/CFW 사진 초기화 정책은 기존 사용자 지시대로 유지한다. 순정 앨범·주행 기록·정비 기준·복구 기록은 이 초기화 대상이 아니다.

## 자원 사용과 CJK 저장 비용

Product에는 이미 별도 버튼 이벤트/화면 상태기계가 있었는데 LVGL encoder/group/theme를 추가 생성한 뒤 비활성화·제거하고 있었다. Product에서 이 중복 초기화를 제거했다. 다른 Graphics 프로필의 encoder 동작은 유지한다. 힙·태스크 스택·통신 큐·예산 기준을 줄이지 않았다. 최종 ELF 수치는 `verification-summary.json`/패키지 `audit.json`에 기록한다.

새 시각 전송 작업 공간은 SDRAM에 입력128KiB, 마스크10.7KiB, JPEG 작업공간4KiB, RGB565 아트 두 장900KiB 및 작은 상태 구조체를 한 번 할당한다. 렌더러 마스크 두 장은 추가21.4KiB SDRAM과 GPU 캐시를 사용한다. GPU의 두480×480 사진 bank와 부분 캡처 구조는 유지한다. 기존92KiB 글꼴/아이콘 캐시의 전체 메뉴 최대 사용량은 실기기에서 추가 계측해야 한다. RAM_G 경계 검사는 사진/캡처 영역 침범을 차단하지만 모든 메뉴의 캐시 여유를 증명하는 것은 아니다.

아래는 **한 굵기, 정사각 셀, 무압축4bpp**의 비트맵 계산이다. 실제 타이트한 글자 박스/압축/OTF·TTF 파일 크기는 다르다. 문자 매핑·메트릭·언어별 글리프 변형·조판 코드는 별도이며, 크기나 굵기를 추가하면 데이터가 더 필요하다.

| 문자 집합 | 글리프 수 | 24px | 32px |
|---|---:|---:|---:|
| 한글 완성형 |11,172|3.07MiB|5.46MiB|
| 기본 BMP 한자 |20,992|5.77MiB|10.25MiB|
| 한글 + 기본 BMP 한자 |32,164|8.83MiB|15.71MiB|
| Unicode17 통합 한자 전체 |101,996|28.01MiB|49.80MiB|

즉 **한글만 외장 NOR에 저장하는 것은 현실적인 선택**이다. 반면 ‘CJK 전부’는 문자 범위·일본어/중국어 글리프 선택·크기·굵기까지 정해야 하며 수십MiB가 된다. 외장 NOR 전체 용량이 전부 빈 공간은 아니다. 현재 대상의 여유 클러스터를 다시 확인하지 않고 설치 가능하다고 결론 내리지 않는다. 이번 음악 방식은 언어 범위와 무관하게 한 화면10.7KiB로 고정되므로 이 용도에는 폰 렌더링을 유지했다.

계산 원본/스크립트는 `font-cost.json`, `font_cost.py`. [Unicode17 데이터](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt), [통합 한자 공식 집계](https://www.unicode.org/irg/docs/n2856-CJKUIv17.pdf)를 사용했다.

## 검증과 남은 범위

- Android 단위시험 및 APK 빌드, Product Release/Debug ELF 및 메모리 예산, 실제 Android production ZIP importer 통과. 개수와 해시는 `verification-summary.json` 참조.
- ARM 실행 시험: 잘못된 CRC/길이/세대/청크 위치, JPEG 완전 디코드와 손상, artwork lease, 사진 저장 PENDING,100회 마스크 교체 시 할당 불변, 동일 텍스처1000회 조회 시 재업로드 없음, display-list fence 및 정지 중 늦은 문자 도착, 메뉴/입력/배경 회귀.
- 테스트 fixture에서 낡은8메뉴/리셋확인창/꺼진 장면 버튼힌트 기대값을 현재6메뉴/즉시리셋/숨김 정책에 맞췄다. 시험을 통과시키기 위해 제품의 버튼 정책을 되돌리지 않았다.
- 이 시험은 실제 GPU 화면 캡처, 정상 RF에서의 전체 업데이트·단절 복구, GPS 야외 주행, 사진 NOR 전원차단,8시간 혼합 부하를 대체하지 않는다. 새 UI의 최종 시각 확인도 남아 있다.
- **알림의 CJK 이미지 표시, 라이더 이름 영구 문자 캐시, CDM 기반 백그라운드 자동 시작/존재 감지, 새 자산까지 바꾸는 무선 업데이트는 미완료**다. 이번 음악 구현을 그 기능들의 완료로 확대 해석하지 않는다. OpenNoodoe 원본과 Cube/vendor 원본은 수정하지 않았다.

사용 파일: `NoodoeCompanion-6.2.apk`, `vehicle015-final/installer.zip`. 기존 CFW에서는 앱의 ‘새 CFW로 업데이트 / 전송 이어가기’ 경로를 사용한다. APK 업데이트만으로 기기 펌웨어의 새 CJK 수신 기능이 생기지는 않는다.
